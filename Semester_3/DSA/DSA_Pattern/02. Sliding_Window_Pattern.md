# DSA Pattern #2: Sliding Window


***

## 1. What is a Sliding Window?

The **Sliding Window** technique is a pattern used to solve problems that involve finding a **subarray or substring** that satisfies some condition — such as a maximum sum, minimum length, or a fixed size — **without recomputing** the same overlapping elements again and again.

Instead of using nested loops to check every possible subarray (which is $O(n^2)$ or worse), a "window" (a contiguous range defined by two pointers, `start` and `end`) **slides across** the array/string, expanding or shrinking as needed, reusing previously computed results.

```
Array: [ 2  1  5  1  3  2 ]

Window sliding across the array:

[ 2  1  5 ] 1  3  2      → window covers index 0-2
  2 [ 1  5  1 ] 3  2     → window slides to index 1-3
  2  1 [ 5  1  3 ] 2     → window slides to index 2-4
  2  1  5 [ 1  3  2 ]    → window slides to index 3-5
```

The key idea: **don't restart from scratch** — just add the new element entering the window and remove the old element leaving it.

***

### How to Identify if a Problem Fits the Sliding Window Pattern

| Signal | Explanation |
| :-- | :-- |
| Problem involves a **contiguous subarray or substring**? | Sliding window only works on contiguous ranges, not arbitrary subsets. |
| Keywords like **"maximum/minimum sum/length/count"** of a subarray? | Strong indicator of sliding window. |
| Is there a **fixed size `k`** mentioned (e.g., "subarray of size k")? | Points to **Fixed-Size Window**. |
| Is there a **condition to satisfy** (e.g., "smallest subarray with sum ≥ target", "longest substring without repeating characters")? | Points to **Variable-Size Window**. |
| Would brute force require **recomputing overlapping ranges** repeatedly? | Sliding window eliminates that redundant work. |

If the problem is about a **contiguous range** and involves a **size or condition constraint**, sliding window is very likely the right pattern.

***

***

## 2. Types of Sliding Window

There are **two main types**:

1. **Fixed-Size Window** — the window size `k` is constant and given.
2. **Variable-Size Window** — the window grows and shrinks dynamically based on a condition.

***

## Type 1: Fixed-Size Sliding Window

### Definition

The window size is **fixed at `k`**. As the window slides one step at a time, **one element enters** from the right and **one element leaves** from the left, keeping the window size constant throughout.

***

### Example Problem

**Find the maximum sum of any subarray of size `k`.**

```
Array: [2, 1, 5, 1, 3, 2]
k = 3
```

***

### Step-by-Step Explanation

1. Compute the sum of the **first `k` elements** — this is the initial window.
2. Slide the window one position to the right:
   - **Add** the new element entering the window.
   - **Subtract** the element that just left the window.
3. Track the **maximum sum** seen across all windows.
4. Repeat until the window reaches the end of the array.

***

### Visual Representation

```
Array: [ 2   1   5   1   3   2 ]     k = 3

Step 1: Initial window [0..2]
[ 2   1   5 ]  1   3   2
  sum = 2+1+5 = 8      → max_sum = 8

Step 2: Slide window → [1..3]
  2 [ 1   5   1 ]  3   2
  sum = 8 - 2 + 1 = 7   → max_sum = 8 (unchanged)

Step 3: Slide window → [2..4]
  2   1 [ 5   1   3 ]  2
  sum = 7 - 1 + 3 = 9   → max_sum = 9

Step 4: Slide window → [3..5]
  2   1   5 [ 1   3   2 ]
  sum = 9 - 5 + 2 = 6   → max_sum = 9 (unchanged)

Final Answer: Maximum sum = 9  (subarray [5, 1, 3])
```

***

### C++ Code (Fixed-Size Window)

```cpp
#include <iostream>
#include <vector>
using namespace std;

int maxSumFixedWindow(vector<int>& arr, int k) {
    int n = arr.size();
    if (n < k) return -1;             // Invalid case

    int windowSum = 0;

    // Step 1: compute sum of first window
    for (int i = 0; i < k; i++) {
        windowSum += arr[i];
    }

    int maxSum = windowSum;

    // Step 2: slide the window across the array
    for (int i = k; i < n; i++) {
        windowSum += arr[i];          // add new element entering window
        windowSum -= arr[i - k];      // remove element leaving window
        maxSum = max(maxSum, windowSum);
    }

    return maxSum;
}

int main() {
    vector<int> arr = {2, 1, 5, 1, 3, 2};
    int k = 3;

    cout << "Maximum sum of subarray size " << k
         << " = " << maxSumFixedWindow(arr, k) << endl;

    return 0;
}
```

**Output:**

```
Maximum sum of subarray size 3 = 9
```

***

### Time and Space Complexity (Fixed-Size)

| Metric | Complexity | Explanation |
| :-- | :-- | :-- |
| Time Complexity | $O(n)$ | Each element is added once and removed once — single pass. |
| Space Complexity | $O(1)$ | Only a running sum and max variable are stored. |

## Type 2: Variable-Size Sliding Window

### Definition

The window size is **not fixed** — it **grows** by moving the `end` pointer and **shrinks** by moving the `start` pointer, based on whether a given **condition** is satisfied or violated. This is used when the problem asks for the **smallest/largest window satisfying a condition**, rather than a fixed length.

***

### Example Problem

**Find the length of the smallest subarray with a sum ≥ target.**

```
Array: [2, 1, 5, 2, 3, 2]
Target = 7
```

***

### Step-by-Step Explanation

1. Initialize `start = 0`, `windowSum = 0`, `minLength = infinity`.
2. Expand the window by moving `end` from left to right, adding `arr[end]` to `windowSum`.
3. **While** `windowSum >= target`:
   - Update `minLength` with the current window size (`end - start + 1`).
   - **Shrink** the window from the left: subtract `arr[start]` and move `start` forward.
4. Continue until `end` reaches the end of the array.
5. Return `minLength` (or 0 if no such window exists).

***

### Visual Representation

```
Array: [ 2   1   5   2   3   2 ]     Target = 7
Index:   0   1   2   3   4   5

end=0: window=[2]            sum=2   → sum < 7, expand
end=1: window=[2,1]          sum=3   → sum < 7, expand
end=2: window=[2,1,5]        sum=8   → sum >= 7 
        minLength = 3 (indices 0-2)
        shrink: remove arr[0]=2 → sum=6, start=1
        sum < 7, stop shrinking

end=3: window=[1,5,2]        sum=8   → sum >= 7 
        minLength = min(3, 3) = 3 (indices 1-3)
        shrink: remove arr[1]=1 → sum=7, start=2
        sum >= 7 
        minLength = min(3, 2) = 2 (indices 2-3)
        shrink: remove arr[2]=5 → sum=2, start=3
        sum < 7, stop shrinking

end=4: window=[2,3]          sum=5   → sum < 7, expand
end=5: window=[2,3,2]        sum=7   → sum >= 7 
        minLength = min(2, 3) = 2 (unchanged)
        shrink: remove arr[3]=2 → sum=5, start=4
        sum < 7, stop shrinking

Final Answer: Smallest subarray length = 2  (subarray [5, 2] at indices 2-3)
```

***

### C++ Code (Variable-Size Window)

```cpp
#include <iostream>
#include <vector>
#include <climits>
using namespace std;

int smallestSubarrayWithSum(vector<int>& arr, int target) {
    int n = arr.size();
    int start = 0;
    int windowSum = 0;
    int minLength = INT_MAX;

    for (int end = 0; end < n; end++) {
        windowSum += arr[end];            // expand window by adding new element

        // shrink window while condition is satisfied
        while (windowSum >= target) {
            minLength = min(minLength, end - start + 1);
            windowSum -= arr[start];      // remove element leaving window
            start++;                      // shrink from the left
        }
    }

    return (minLength == INT_MAX) ? 0 : minLength;
}

int main() {
    vector<int> arr = {2, 1, 5, 2, 3, 2};
    int target = 7;

    cout << "Smallest subarray length with sum >= " << target
         << " = " << smallestSubarrayWithSum(arr, target) << endl;

    return 0;
}
```

**Output:**

```
Smallest subarray length with sum >= 7 = 2
```

***

### Time and Space Complexity (Variable-Size)

| Metric | Complexity | Explanation |
| :-- | :-- | :-- |
| Time Complexity | $O(n)$ | Although there's a nested `while` loop, `start` only moves forward — each element is visited at most twice (once by `end`, once by `start`), so total work is linear. |
| Space Complexity | $O(1)$ | Only a few pointer/sum variables are used (no extra structures needed for sums; would be $O(k)$ if tracking character frequency, e.g., for substring problems). |

## Fixed vs Variable Window — Quick Comparison

| Aspect | Fixed-Size Window | Variable-Size Window |
| :-- | :-- | :-- |
| Window size | Constant (`k`), given upfront | Changes dynamically based on a condition |
| Pointer movement | Both `start` and `end` move together, one step at a time | `end` expands, `start` shrinks independently |
| Typical question phrasing | "subarray of size `k`" | "smallest/longest subarray/substring satisfying..." |
| Example problems | Max sum of subarray size k, average of subarrays | Smallest subarray with sum ≥ target, longest substring without repeating characters |
| Time Complexity | $O(n)$ | $O(n)$ (amortized, due to two-pointer style movement) |
| Space Complexity | $O(1)$ | $O(1)$ to $O(k)$ (depends on whether extra tracking, like a hashmap, is needed) |

***

## Common Problems Solved Using Sliding Window Pattern

**Fixed-Size Window:**
- Maximum/minimum sum of subarray of size k
- Average of all subarrays of size k
- Maximum number of vowels in a substring of length k

**Variable-Size Window:**
- Smallest subarray with a sum ≥ target
- Longest substring without repeating characters
- Longest substring with at most K distinct characters
- Minimum window substring (containing all characters of another string)

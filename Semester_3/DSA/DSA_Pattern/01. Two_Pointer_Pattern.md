# DSA Patterns


***

## 1. What is a DSA Pattern?

A **DSA pattern** is a **reusable strategy or technique** used to solve a category of problems that share a common underlying structure — even if the problems look different on the surface.

Instead of treating every coding problem as a brand-new puzzle, patterns let you **recognize the "shape"** of a problem and apply a known, proven approach to solve it efficiently.

**Example:**

```
Problem A: "Find pair with given sum in sorted array"
Problem B: "Remove duplicates from sorted array"
Problem C: "Find if a string is a palindrome"
```

These look unrelated, but all three can be solved using the **same pattern** — the **Two-Pointer approach**.

***

## 2. Why is Pattern Recognition Important After Learning DSA?

Once you've learned individual data structures (arrays, trees, linked lists) and algorithms (sorting, searching, traversals), the next big leap is **connecting problems to patterns**.

- **Interview problems are rarely "new"** — most map back to ~15-20 recurring patterns.
- Without pattern recognition, you re-derive a solution from scratch every time, which is **slow and error-prone**.
- With pattern recognition, you **identify the pattern first**, then adapt the template — turning a "hard" problem into a "familiar" one.

**Example:**

```
Without pattern thinking:
  "I don't know where to start..." (brute force, O(n²), timeout)

With pattern thinking:
  "Sorted array + pair sum → Two Pointers" → O(n) solution instantly
```

***

## 3. Pros of Learning Patterns

- **Faster problem-solving** — you spend less time exploring and more time executing.
- **Better time complexity** — patterns often convert brute-force $O(n^2)$ or $O(n^3)$ solutions into $O(n)$ or $O(n \log n)$.
- **Transferable skill** — one pattern solves dozens of differently-worded problems.
- **Interview confidence** — you can classify a new problem within seconds by matching its structure to a known pattern.
- **Reduces cognitive load** — you memorize *templates*, not hundreds of unrelated solutions.

## 4. Pattern #1: Two-Pointer Approach

### Definition

The **Two-Pointer technique** uses **two index variables (pointers)** that traverse a data structure (usually an array or string) — either:

- **Moving toward each other** (from opposite ends), or
- **Moving in the same direction** (one ahead of the other, e.g., slow/fast pointers)

...to solve a problem in a **single pass**, avoiding the need for nested loops.

```
Opposite-direction pointers:

  [ 2   4   6   8   10 ]
    ↑                 ↑
   left              right
   (moves right →)   (← moves left)
```

```
Same-direction pointers:

  [ 2   4   4   6   8 ]
    ↑   ↑
  slow fast
  (fast scans ahead, slow marks position)
```

***

### How to Identify if a Problem Fits the Two-Pointer Pattern

Ask yourself these questions:

| Signal | Explanation |
| :-- | :-- |
| Is the input a **sorted array or string**? | Two pointers exploit ordering to decide which side to move. |
| Are you looking for a **pair/triplet** with a target sum, difference, or product? | Classic two-pointer scenario. |
| Do you need to **compare elements from both ends**? | E.g., palindrome check. |
| Are you asked to **remove duplicates / partition in-place**? | Same-direction (slow-fast) pointer pattern. |
| Would a brute-force solution use **nested loops (O(n²))** to check every pair? | Two pointers usually reduce this to O(n). |
| Is there a **linked list cycle / middle-node** question? | Fast-slow pointer variant applies. |

If **2 or more** of the above are true, the problem is very likely solvable using the Two-Pointer pattern.

***

### Step-by-Step Explanation with a Simple Example

**Problem:** Given a **sorted array**, find if there exists a **pair of numbers** that sum to a given target.

```
Array:  [2, 7, 11, 15]
Target: 9
```

**Algorithm:**

1. Place `left` pointer at the **start** of the array (index 0).
2. Place `right` pointer at the **end** of the array (last index).
3. Compute `sum = arr[left] + arr[right]`.
4. Compare `sum` with `target`:
   - If `sum == target` → pair found, return indices/values.
   - If `sum < target` → move `left` pointer **rightward** (need a bigger sum).
   - If `sum > target` → move `right` pointer **leftward** (need a smaller sum).
5. Repeat until `left < right`. If no pair found, return false.

***

### Visual Execution

```
Array:  [2, 7, 11, 15]     Target = 9
Index:   0  1   2   3

Step 1:
[ 2   7   11   15 ]
  ↑            ↑
 left(0)     right(3)
 sum = 2 + 15 = 17   → 17 > 9  → move right pointer LEFT


Step 2:
[ 2   7   11   15 ]
  ↑        ↑
 left(0)  right(2)
 sum = 2 + 11 = 13   → 13 > 9  → move right pointer LEFT


Step 3:
[ 2   7   11   15 ]
  ↑    ↑
 left(0) right(1)
 sum = 2 + 7 = 9     → 9 == 9  ✅ PAIR FOUND: (2, 7)
```

Total steps taken: **3** (instead of checking all 6 possible pairs in brute force) — this is the efficiency gain of the pattern.

***

### C++ Code

```cpp
#include <iostream>
#include <vector>
using namespace std;

// Returns true if a pair with the given target sum exists
bool twoSumSorted(vector<int>& arr, int target) {
    int left = 0;                     // Pointer at the start
    int right = arr.size() - 1;       // Pointer at the end

    while (left < right) {
        int sum = arr[left] + arr[right];

        if (sum == target) {
            cout << "Pair found: (" << arr[left] << ", " << arr[right] << ")" << endl;
            return true;               // Pair found
        }
        else if (sum < target) {
            left++;                    // Need a larger sum, move left pointer right
        }
        else {
            right--;                   // Need a smaller sum, move right pointer left
        }
    }
    return false;                      // No pair found
}

int main() {
    vector<int> arr = {2, 7, 11, 15};
    int target = 9;

    if (!twoSumSorted(arr, target)) {
        cout << "No pair found with sum " << target << endl;
    }
    return 0;
}
```

**Output:**

```
Pair found: (2, 7)
```

***

### Time and Space Complexity

| Metric | Complexity | Explanation |
| :-- | :-- | :-- |
| Time Complexity | $O(n)$ | Each pointer moves at most $n$ steps total, so the array is traversed once. |
| Space Complexity | $O(1)$ | Only two pointer variables are used — no extra data structures. |

**Comparison with Brute Force:**

| Approach | Time Complexity | Space Complexity |
| :-- | :-- | :-- |
| Brute Force (nested loops) | $O(n^2)$ | $O(1)$ |
| Two-Pointer Approach | $O(n)$ | $O(1)$ |

## Common Problems Solved Using Two-Pointer Pattern

- Pair with given sum in a sorted array
- Removing duplicates from a sorted array (in-place)
- Reversing an array or string
- Checking if a string is a palindrome
- Merging two sorted arrays
- Container With Most Water
- Trapping Rain Water
- 3Sum / 4Sum (combined with sorting)
- Detecting a cycle in a linked list (Floyd's fast-slow variant)

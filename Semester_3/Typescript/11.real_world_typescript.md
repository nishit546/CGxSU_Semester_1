# Real-World

## 1. API Typing

TypeScript can be used to describe the data exchanged between applications and APIs.

API types can define request data, response data, errors, pagination, and client interfaces.

---

## HTTP Request Typing

HTTP requests can be represented using specific types for:

- Request body
- Query parameters
- Path parameters
- Headers

```ts
interface CreateUserRequest {
  name: string;
  email: string;
}
```

The type describes the expected request body.

---

## HTTP Response Typing

API responses can be represented using interfaces or type aliases.

```ts
interface User {
  id: number;
  name: string;
}

interface GetUserResponse {
  data: User;
}
```

Response types allow TypeScript to check how returned API data is consumed.

---

## Generic API Responses

A generic type can represent a reusable API response structure.

```ts
interface ApiResponse<T> {
  data: T;
  success: boolean;
  message: string;
}
```

Different endpoints can supply different data types.

```ts
type UserResponse = ApiResponse<User>;
type UsersResponse = ApiResponse<User[]>;
```

---

## Pagination Types

Pagination information can be modeled using reusable types.

```ts
interface Pagination {
  page: number;
  limit: number;
  total: number;
  totalPages: number;
}

interface PaginatedResponse<T> {
  data: T[];
  pagination: Pagination;
}
```

The generic type allows the same pagination structure to be reused for different resources.

---

## Error Response Types

API errors can be represented with dedicated types.

```ts
interface ApiError {
  success: false;
  message: string;
  code: string;
}
```

Success and error responses can also be represented using a discriminated union.

```ts
type ApiResult<T> =
  | {
      success: true;
      data: T;
    }
  | {
      success: false;
      error: ApiError;
    };
```

---

## API Client Types

An API client can use TypeScript types to describe the requests and responses of API operations.

```ts
interface UserApi {
  getUser(id: number): Promise<User>;
  getUsers(): Promise<User[]>;
}
```

This provides type checking for code that communicates with the API.

Generic API clients can be used when the request and response structures vary between endpoints.

---

# 2. Data Modeling

Data modeling involves defining types that represent application data and how that data changes between different layers.

---

## Entity Types

Entity types represent core objects in an application.

```ts
interface User {
  id: number;
  name: string;
  email: string;
}
```

An entity type commonly represents a record that has an identity within the application or database.

---

## DTO Types

DTO stands for Data Transfer Object.

DTOs describe the shape of data transferred between application boundaries.

```ts
interface CreateUserDto {
  name: string;
  email: string;
}
```

DTOs can differ from database entities because different layers may require different fields.

---

## Database Types

Database types represent the structure of data stored in a database.

```ts
interface UserRecord {
  id: number;
  name: string;
  email: string;
  createdAt: Date;
}
```

Database types can represent columns, relationships, and database-specific data structures.

---

## Create Types

Create types represent the fields required when creating a new entity.

```ts
type CreateUser = {
  name: string;
  email: string;
};
```

Fields generated by the database, such as an ID, may not be included.

---

## Update Types

Update types represent fields that can be changed after an entity has been created.

```ts
type UpdateUser = {
  name?: string;
  email?: string;
};
```

Update types commonly use optional properties because an update may change only some fields.

---

## Partial Models

`Partial<T>` can be used to create a type where all properties are optional.

```ts
type UpdateUser = Partial<User>;
```

This is useful for partial updates, configuration objects, and other situations where only some properties are provided.

---

## Nested Models

Types can contain nested objects and collections.

```ts
interface User {
  id: number;
  profile: {
    firstName: string;
    lastName: string;
  };
}
```

Nested models can represent complex application data structures.

---

## Relationship Types

Relationship types describe connections between entities.

```ts
interface User {
  id: number;
  posts: Post[];
}

interface Post {
  id: number;
  title: string;
}
```

Relationships can represent:

- One-to-one
- One-to-many
- Many-to-many

The type structure should represent the data actually available at the boundary where it is used.

---

# 3. Type-safe Architecture

TypeScript can be used across application layers to create clear type boundaries and reduce mismatches between different parts of a system.

---

## Shared Types

Shared types describe structures used by multiple parts of an application.

```ts
export interface User {
  id: number;
  name: string;
}
```

Shared types can be used by multiple layers or applications when they represent a genuinely shared contract.

Types should not be shared unnecessarily when two layers have different responsibilities.

---

## Domain Types

Domain types represent concepts and rules that are specific to the application's business domain.

```ts
type UserId = string & {
  readonly __brand: "UserId";
};
```

Domain types can provide stronger guarantees for important business values.

---

## Type Boundaries

A type boundary is a point where data enters or leaves a part of the application.

Common boundaries include:

- API requests
- API responses
- Database access
- User input
- External services
- Configuration

Data should be typed at these boundaries rather than assuming that external data automatically matches an internal type.

---

## Configuration Types

Application configuration can be represented with a dedicated type.

```ts
interface Config {
  port: number;
  databaseUrl: string;
  environment: "development" | "production";
}
```

A configuration type provides a clear contract for application settings.

---

## Environment Types

Environment variables are typically provided as strings or may be absent.

```ts
const port = process.env.PORT;
```

TypeScript does not automatically guarantee that an environment variable exists or has the expected format.

Environment values should therefore be validated and converted before being used as strongly typed application configuration.

---

## Layer Separation Patterns

Types can be separated according to application layers.

A common structure is:

```text
API Layer
    ↓
DTOs
    ↓
Domain Layer
    ↓
Services
    ↓
Repository Layer
    ↓
Database
```

Each layer can have types appropriate to its responsibility.

This avoids forcing one type to represent every form of the same data across the entire application.

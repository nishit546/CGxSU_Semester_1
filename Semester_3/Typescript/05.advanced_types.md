# Advanced Types

## 1. Enums

Enums allow a set of named constants to be defined.

```ts
enum Role {
	Admin,
	User,
	Guest,
}
```

Enums are a TypeScript feature that can generate JavaScript runtime code.

---

## Numeric Enums

Numeric enums assign numeric values to members.

```ts
enum Status {
	Pending,
	Success,
	Error,
}
```

By default, the first member receives `0`, and subsequent members are incremented.

Numeric values can also be assigned explicitly.

```ts
enum Status {
	Pending = 1,
	Success = 2,
	Error = 3,
}
```

---

## String Enums

String enums assign string values to members.

```ts
enum Role {
	Admin = "ADMIN",
	User = "USER",
	Guest = "GUEST",
}
```

String enums provide explicit runtime values for each member.

---

## Heterogeneous Enums

Heterogeneous enums contain both numeric and string members.

```ts
enum Value {
	Number = 1,
	String = "string",
}
```

Although supported, heterogeneous enums are generally uncommon because mixing value types can make an enum harder to reason about.

---

## Const Enums

Const enums use the `const` modifier.

```ts
const enum Direction {
	Up,
	Down,
	Left,
	Right,
}
```

Their members can be inlined during compilation instead of producing a normal runtime enum object.

Const enums have restrictions and can have compatibility implications depending on the build configuration.

---

## Computed Enum Members

Enum members can use computed values.

```ts
enum Status {
	Start = 1,
	Next = Start + 1,
}
```

Computed members are evaluated according to TypeScript's enum rules.

---

## Enum Runtime Behavior

Regular enums exist at runtime as JavaScript objects.

```ts
enum Role {
	Admin,
	User,
}
```

The generated JavaScript contains runtime code for the enum.

Numeric enums also have reverse mappings in their generated runtime representation.

String enums do not have the same reverse mapping behavior.

---

## Enum Alternatives

Literal unions and `as const` objects can often be used instead of enums.

```ts
const roles = ["ADMIN", "USER", "GUEST"] as const;

type Role = (typeof roles)[number];
```

These approaches can provide type safety while keeping the runtime representation explicit and lightweight.

---

# 2. Generics

Generics allow types to be passed as parameters to functions, interfaces, type aliases, and classes.

They make reusable code possible without losing type information.
A generic introduces a type parameter that is determined when the generic is used.

---

## Generic Functions

Functions can define one or more generic type parameters.

```ts
function first<T>(items: T[]): T {
	return items[0];
}
```

The function can work with arrays of different types while preserving the element type.

---

## Generic Interfaces

Interfaces can accept generic type parameters.

```ts
interface ApiResponse<T> {
	data: T;
	success: boolean;
}
```

The type of `data` is determined when the interface is used.

```ts
type UserResponse = ApiResponse<User>;
```

---

## Generic Classes

Classes can use generic type parameters.

```ts
class Box<T> {
	constructor(public value: T) {}
}
```

The type of `value` is determined when the class is instantiated.

---

## Multiple Type Parameters

A generic can define multiple type parameters.

```ts
function pair<T, U>(first: T, second: U): [T, U] {
	return [first, second];
}
```

Each type parameter can represent a different type.

---

## Generic Constraints

Generic constraints restrict which types can be supplied as generic arguments.

```ts
function getId<T extends { id: number }>(value: T): number {
	return value.id;
}
```

`T` must have an `id` property of type `number`.

---

## `extends` with Generics

The `extends` keyword is used to define constraints on generic parameters.

```ts
function getLength<T extends { length: number }>(value: T) {
	return value.length;
}
```

Only types that have a compatible `length` property can be used.

## Generic Callbacks

Callbacks can use generic types.

```ts
function mapValue<T, U>(value: T, callback: (value: T) => U): U {
	return callback(value);
}
```

The callback receives the same type represented by `T` and produces the type represented by `U`.

---

## Generic Utility Patterns

Generics are commonly used to create reusable patterns for:

- API responses
- Collections
- Repositories
- Pagination
- Data transformations
- Utility functions

---

# 3. Type Assertions

Type assertions tell TypeScript to treat a value as a specific type.

They do not perform runtime type validation or conversion.

```ts
const value = someValue as string;
```

---

## `as` Syntax

The `as` syntax is the standard form of type assertion.

```ts
const element = document.getElementById("app") as HTMLElement;
```

The assertion changes how TypeScript treats the value during type checking.

It does not change the runtime value.

---

## Angle-Bracket Syntax

Type assertions can also use angle-bracket syntax.

```ts
const value = <string>someValue;
```

This syntax cannot be used in `.tsx` files because it conflicts with JSX syntax.

The `as` syntax is therefore commonly preferred in React and JSX-based projects.

---

## Non-null Assertion

The non-null assertion operator `!` tells TypeScript that a value is not `null` or `undefined`.

```ts
const element = document.getElementById("app")!;
```

The operator only affects TypeScript's type checking. It does not perform a runtime check.

If the value is actually `null` or `undefined`, a runtime error can still occur.

---

## Double Assertions

A value can sometimes be asserted through an intermediate type.

```ts
const value = someValue as unknown as string;
```

Double assertions bypass normal compatibility checks between types.

They should be used carefully because they can remove type safety.

---

## Type Assertion Limitations

Type assertions:

- Do not validate data at runtime
- Do not convert values
- Do not change the actual JavaScript value
- Can hide incorrect assumptions
- Should not be used as a replacement for runtime validation

---

# 4. `keyof` & `typeof`

## `keyof`

The `keyof` operator produces a union of the known property keys of a type.

```ts
type User = {
	id: number;
	name: string;
};

type UserKey = keyof User;
```

`UserKey` becomes:

```text
"id" | "name"
```

---

## Type-level `typeof`

TypeScript's type-level `typeof` operator can obtain the type of an existing value.

```ts
const user = {
	id: 1,
	name: "Satya",
};

type User = typeof user;
```

This is different from JavaScript's runtime `typeof` operator.

---

## `keyof typeof`

`keyof` and type-level `typeof` can be combined to obtain the keys of a value.

```ts
const roles = {
	admin: "ADMIN",
	user: "USER",
} as const;

type RoleKey = keyof typeof roles;
```

The resulting type is:

```text
"admin" | "user"
```

---

## Indexed Access Types

Indexed access types retrieve the type of a property using bracket notation.

```ts
type User = {
	id: number;
	name: string;
};

type UserName = User["name"];
```

`UserName` is `string`.

Multiple properties can also be accessed.

```ts
type UserValue = User["id" | "name"];
```

The resulting type is:

```text
number | string
```

---

## Dynamic Property Types

`keyof` and indexed access types can be used together to work with dynamic property names while preserving type safety.

```ts
function getProperty<T, K extends keyof T>(object: T, key: K): T[K] {
	return object[key];
}
```

The return type depends on the property selected.

---

# 5. Mapped Types

Mapped types create new types by transforming the properties of an existing type.

```ts
type User = {
	id: number;
	name: string;
};

type ReadonlyUser = {
	readonly [K in keyof User]: User[K];
};
```

---

## Mapping Over Keys

The `in` keyword is used to iterate over the keys of a type.

```ts
type Optional<T> = {
	[K in keyof T]?: T[K];
};
```

For every property in `T`, the mapped type creates a corresponding optional property.

---

## Optional Modifiers

Mapped types can add the optional `?` modifier.

```ts
type Optional<T> = {
	[K in keyof T]?: T[K];
};
```

They can also remove the modifier using `-?`.

```ts
type Required<T> = {
	[K in keyof T]-?: T[K];
};
```

---

## Readonly Modifiers

Mapped types can add `readonly`.

```ts
type ReadonlyType<T> = {
	readonly [K in keyof T]: T[K];
};
```

The modifier can be removed using `-readonly`.

```ts
type Mutable<T> = {
	-readonly [K in keyof T]: T[K];
};
```

---

## Removing Modifiers

Mapped types support `+` and `-` modifiers.

```ts
type Optional<T> = {
	[K in keyof T]?: T[K];
};

type Required<T> = {
	[K in keyof T]-?: T[K];
};

type ReadonlyType<T> = {
	readonly [K in keyof T]: T[K];
};

type Mutable<T> = {
	-readonly [K in keyof T]: T[K];
};
```

The `+` modifier is the default and is usually omitted.

---

## Key Remapping

Mapped types can rename keys using `as`.

```ts
type PrefixKeys<T> = {
	[K in keyof T as `get${Capitalize<string & K>}`]: T[K];
};
```

Key remapping allows the generated property names to differ from the original keys.

---

## Conditional Mapped Types

Mapped types can contain conditional types to transform properties differently based on their types.

```ts
type StringProperties<T> = {
	[K in keyof T]: T[K] extends string ? T[K] : never;
};
```

Mapped and conditional types can be combined to create advanced type transformations.

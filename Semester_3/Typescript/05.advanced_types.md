# Advanced Types

## 1. Enums

Enums allow a set of named constants to be defined.

```ts
enum Role {
	Admin,
	User,
	Guest,
}
```

Enums are a TypeScript feature that can generate JavaScript runtime code.

---

## Using Enums as Types

An enum can be used as the type of a variable, parameter, property, or return value.

```ts
enum OrderStatus {
	Pending,
	Confirmed,
	Delivered,
	Cancelled,
}

let status: OrderStatus = OrderStatus.Pending;

function updateStatus(status: OrderStatus): void {
	console.log(status);
}

updateStatus(OrderStatus.Confirmed);
```

This prevents invalid values from being passed to the function.

---

## Numeric Enums

Numeric enums assign numeric values to members.

```ts
enum Status {
	Pending,
	Success,
	Error,
}
```

By default, the first member receives `0`, and subsequent members are incremented.

```ts
console.log(Status.Pending); // 0
console.log(Status.Success); // 1
console.log(Status.Error);   // 2
```

Numeric values can also be assigned explicitly.

```ts
enum Status {
	Pending = 1,
	Success = 2,
	Error = 3,
}
```

Explicit numeric values can be useful when working with predefined codes from another system.

```ts
enum ResponseCode {
	Success = 200,
	Created = 201,
	BadRequest = 400,
	NotFound = 404,
}
```

---

## String Enums

String enums assign string values to members.

```ts
enum Role {
	Admin = "ADMIN",
	User = "USER",
	Guest = "GUEST",
}
```

String enums provide explicit runtime values for each member.

Unlike numeric enums, string enum members do not automatically receive incrementing values. Each member should have an explicit string value.

```ts
enum PaymentMethod {
	Cash = "cash",
	Card = "card",
	UPI = "upi",
}
```

String enums are commonly useful for values such as:

* Order status
* Payment methods
* User roles
* Environment names
* Categories
* Permission names

---

## Using Enums with Objects

Enums can be used to restrict object properties to a known set of values.

```ts
enum OrderStatus {
	Pending = "pending",
	Confirmed = "confirmed",
	Delivered = "delivered",
	Cancelled = "cancelled",
}

type Order = {
	id: number;
	status: OrderStatus;
};

const order: Order = {
	id: 101,
	status: OrderStatus.Pending,
};
```

---

## Using Enums with `switch`

Enums work well with `switch` statements when different behavior is required for each value.

```ts
enum PaymentMethod {
	Cash = "cash",
	Card = "card",
	UPI = "upi",
}

function processPayment(method: PaymentMethod): void {
	switch (method) {
		case PaymentMethod.Cash:
			console.log("Processing cash payment");
			break;

		case PaymentMethod.Card:
			console.log("Processing card payment");
			break;

		case PaymentMethod.UPI:
			console.log("Processing UPI payment");
			break;
	}
}
```

---

## Computed Enum Members

Enum members can use computed values.

```ts
enum Status {
	Start = 1,
	Next = Start + 1,
}
```

Computed members are evaluated according to TypeScript's enum rules.

Another example:

```ts
enum Priority {
	Low = 1,
	Medium = Low + 1,
	High = Medium + 1,
	Critical = High + 1,
}
```

---

## Enum Runtime Behavior

Regular enums exist at runtime as JavaScript objects.

```ts
enum Role {
	Admin,
	User,
}
```

The generated JavaScript contains runtime code for the enum.

This means the enum can be accessed at runtime:

```ts
console.log(Role.Admin);
```

Numeric enums also have reverse mappings in their generated runtime representation.

```ts
enum Role {
	Admin,
	User,
}

console.log(Role.Admin); // 0
console.log(Role[0]);    // "Admin"
```

String enums do not have the same reverse mapping behavior.

---

## Enum Alternatives

Literal unions and `as const` objects can often be used instead of enums.

### Literal Union

```ts
type Role = "ADMIN" | "USER" | "GUEST";
```

### `as const` Object

```ts
const roles = {
	Admin: "ADMIN",
	User: "USER",
	Guest: "GUEST",
} as const;
```

A type can be created from the values:

```ts
type Role = (typeof roles)[keyof typeof roles];
```

These approaches can provide type safety while keeping the runtime representation explicit and lightweight.

---

## Enum vs Literal Union

Both approaches can restrict a value to a fixed set of options.

### Enum

```ts
enum OrderStatus {
	Pending = "pending",
	Confirmed = "confirmed",
	Delivered = "delivered",
}
```

Usage:

```ts
const status = OrderStatus.Pending;
```

### Literal Union

```ts
type OrderStatus =
	| "pending"
	| "confirmed"
	| "delivered";
```

Usage:

```ts
const status: OrderStatus = "pending";
```

Use an enum when having named members and a runtime enum object is useful.

Use a literal union when you only need to restrict values at the TypeScript type level.

# 2. Generics

Generics allow us to write reusable code that can work with different types while still preserving type safety.

Instead of creating separate functions for `string`, `number`, `User`, `Product`, etc., we can create one reusable function and let TypeScript determine the type when it is used.

---

## Generic Functions

A function can use a generic type parameter such as `T`.

```ts
function first<T>(items: T[]): T {
	return items[0];
}
```

The same function can work with different types:

```ts
const number = first([10, 20, 30]);

const name = first(["John", "Alex", "Sam"]);
```

TypeScript understands:

```text
number → number
name   → string
```

### Real-world use

Generic functions are useful for reusable operations such as:

* Getting an item from an array
* Finding a record
* Transforming data
* Working with reusable utility functions

For example:

```ts
function getFirstItem<T>(items: T[]): T {
	return items[0];
}
```

This function can work with:

```ts
getFirstItem(users);
getFirstItem(products);
getFirstItem(orders);
```

without creating three different functions.

---

## Generic Interfaces

Interfaces can also accept a generic type.

```ts
interface ApiResponse<T> {
	data: T;
	success: boolean;
}
```

The type of `data` is determined when the interface is used.

```ts
type UserResponse = ApiResponse<User>;

type ProductResponse = ApiResponse<Product>;
```

For example:

```ts
const userResponse: UserResponse = {
	data: user,
	success: true,
};
```

### Real-world use

This pattern is very common when working with API responses.

Instead of creating:

```ts
UserResponse
ProductResponse
OrderResponse
```

separately, we can create one reusable structure:

```ts
ApiResponse<T>
```

and provide the required data type.

```text
ApiResponse<User>
ApiResponse<Product>
ApiResponse<Order>
```

---

## Multiple Type Parameters

A generic can have more than one type parameter.

```ts
function pair<T, U>(first: T, second: U): [T, U] {
	return [first, second];
}
```

The two values can have different types:

```ts
const result = pair(101, "Order");
```

TypeScript understands:

```ts
// [number, string]
```

Another example:

```ts
const userWithId = pair(101, user);
```

Here:

```text
T → number
U → User
```

### Real-world use

Multiple type parameters are useful when a function works with **two related but different types**.

For example:

```ts
pair(userId, user);
pair(productId, product);
pair(orderId, order);
```

---

## Generic Constraints

Sometimes we don't want to allow every possible type.

A generic constraint allows us to require certain properties.

```ts
function getId<T extends { id: number }>(value: T): number {
	return value.id;
}
```

`T` must have an `id` property of type `number`.

Therefore, these can be used:

```ts
getId(user);
getId(product);
getId(order);
```

as long as they contain:

```ts
id: number
```

### Real-world use

This is useful when different objects share a common property.

For example:

```ts
type User = {
	id: number;
	name: string;
};

type Product = {
	id: number;
	name: string;
	price: number;
};
```

Both have an `id`, so the same function can work with both:

```ts
getId(user);
getId(product);
```

without losing their original types.

---

## Practical Example

Imagine an application that stores different types of records:

```ts
type User = {
	id: number;
	name: string;
};

type Product = {
	id: number;
	name: string;
	price: number;
};
```

Instead of creating separate functions:

```ts
getUserId(user);
getProductId(product);
```

we can create one reusable function:

```ts
function getId<T extends { id: number }>(value: T): number {
	return value.id;
}
```

Now:

```ts
getId(user);
getId(product);
```

One function works with both types while TypeScript still knows what type was provided.

---

## Key Idea

When you see:

```ts
<T>
```

think:

> "This code should work with different types, and TypeScript should remember which type I'm using."

When you see:

```ts
<T extends Something>
```

think:

> "This code should work with different types, but they must satisfy a specific requirement."

## 3. Type Assertions

Type assertions tell TypeScript to treat a value as a specific type.

They **do not perform runtime validation or conversion**.

```ts
const value = someValue as string;
```

---

## `as` Syntax

The `as` syntax is the standard way to write a type assertion.

```ts
const element = document.getElementById("app") as HTMLElement;
```

The assertion changes how TypeScript treats the value during type checking.

It **does not change the actual runtime value**.

### Real-world example

Sometimes TypeScript cannot determine the exact type of data we know is correct.

```ts
const input = document.getElementById("username") as HTMLInputElement;

console.log(input.value);
```

Here, we are telling TypeScript:

> "I know this element is an `HTMLInputElement`."

---

## Non-null Assertion `!`

The non-null assertion operator `!` tells TypeScript that a value is **not `null` or `undefined`**.

```ts
const element = document.getElementById("app")!;
```

Without `!`, TypeScript may consider the value:

```ts
HTMLElement | null
```

With `!`, TypeScript treats it as:

```ts
HTMLElement
```

### Important

The `!` operator does **not** perform a runtime check.

```ts
const element = document.getElementById("app")!;

element.innerHTML = "Hello";
```

If the element does not exist, the value can still be `null` at runtime and the code can fail.

So use `!` only when you are confident the value exists.

---

## Type Assertion Limitations

Type assertions:

* Do not validate data at runtime.
* Do not convert values.
* Do not change the actual JavaScript value.
* Can hide incorrect assumptions.
* Should not replace runtime validation.

For example:

```ts
const value = "123" as unknown as number;
```

This does **not** convert `"123"` into `123`.

The runtime value is still:

```ts
"123"
```

### Key idea

> Type assertion tells TypeScript what you believe the value is. It does not make the value become that type.

---

# 4. `keyof` & `typeof`

These operators are mainly useful when working with **existing types and objects dynamically**.

---

## `keyof`

The `keyof` operator produces a union of the known property keys of a type.

```ts
type User = {
	id: number;
	name: string;
	email: string;
};

type UserKey = keyof User;
```

`UserKey` becomes:

```ts
"id" | "name" | "email"
```

This is useful when we want to restrict a value to the valid property names of an object.

### Real-world example

```ts
function printKey(key: keyof User) {
	console.log(key);
}

printKey("name");  // valid
printKey("email"); // valid
```

This would be an error:

```ts
printKey("age");
```

because `"age"` is not a key of `User`.

---

## Type-level `typeof`

TypeScript's type-level `typeof` can obtain the type of an existing value.

```ts
const user = {
	id: 1,
	name: "Satya",
};

type User = typeof user;
```

TypeScript creates a type similar to:

```ts
type User = {
	id: number;
	name: string;
};
```

### Important

This is different from JavaScript's runtime `typeof`.

JavaScript:

```ts
typeof user;
```

returns a runtime string such as:

```text
"object"
```

TypeScript:

```ts
type User = typeof user;
```

gets the **TypeScript type** of the value.

---

## `keyof typeof`

`keyof` and type-level `typeof` can be combined.

This is especially useful when we have an object and want a type containing its keys.

```ts
const roles = {
	admin: "ADMIN",
	user: "USER",
	guest: "GUEST",
} as const;

type RoleKey = keyof typeof roles;
```

`RoleKey` becomes:

```ts
"admin" | "user" | "guest"
```

### Real-world example

```ts
function getRoleLabel(role: keyof typeof roles) {
	return roles[role];
}

getRoleLabel("admin"); // valid
getRoleLabel("user");  // valid
```

This prevents invalid keys:

```ts
getRoleLabel("manager"); // Error
```

---

## Indexed Access Types

Indexed access types allow us to get the type of a property using bracket notation.

```ts
type User = {
	id: number;
	name: string;
};

type UserName = User["name"];
```

`UserName` becomes:

```ts
string
```

Similarly:

```ts
type UserId = User["id"];
```

becomes:

```ts
number
```

We can also access multiple properties:

```ts
type UserValue = User["id" | "name"];
```

The result is:

```ts
number | string
```

### Key idea

Think of it as:

```ts
User["name"]
```

meaning:

> "Give me the type of the `name` property from `User`."

---

## Dynamic Property Types

`keyof` and indexed access types can be combined to safely work with dynamic property names.

```ts
function getProperty<T, K extends keyof T>(
	object: T,
	key: K
): T[K] {
	return object[key];
}
```

Example:

```ts
const user = {
	id: 1,
	name: "Satya",
};
```

Now:

```ts
const name = getProperty(user, "name");
```

TypeScript knows:

```ts
name: string
```

And:

```ts
const id = getProperty(user, "id");
```

TypeScript knows:

```ts
id: number
```

An invalid property is rejected:

```ts
getProperty(user, "age"); // Error
```

### Why is this useful?

It allows us to create reusable functions that work with different objects while still maintaining type safety.

# 5. Mapped Types

Mapped types create a new type by transforming the properties of an existing type.

They are useful when we want to create variations of an existing type.

---

## Basic Mapped Types

Consider:

```ts
type User = {
	id: number;
	name: string;
};
```

We can create a readonly version:

```ts
type ReadonlyUser = {
	readonly [K in keyof User]: User[K];
};
```

This produces:

```ts
type ReadonlyUser = {
	readonly id: number;
	readonly name: string;
};
```

The important part is:

```ts
[K in keyof User]
```

It means:

> "Go through every key in `User`."

---

## Mapping Over Keys

The `in` keyword is used to iterate over the keys of a type.

```ts
type Optional<T> = {
	[K in keyof T]?: T[K];
};
```

Example:

```ts
type User = {
	id: number;
	name: string;
};
```

Now:

```ts
type OptionalUser = Optional<User>;
```

becomes:

```ts
type OptionalUser = {
	id?: number;
	name?: string;
};
```

### Real-world use

This pattern is useful when creating update or patch objects.

```ts
type UserUpdate = Optional<User>;
```

Now we can update only the properties we need:

```ts
const update: UserUpdate = {
	name: "John",
};
```

---

## Optional Modifiers

Mapped types can add the optional `?` modifier.

```ts
type Optional<T> = {
	[K in keyof T]?: T[K];
};
```

For example:

```ts
type Product = {
	id: number;
	name: string;
	price: number;
};

type ProductUpdate = Optional<Product>;
```

Now all properties are optional:

```ts
const update: ProductUpdate = {
	price: 999,
};
```

This is useful for things like:

* Update requests
* PATCH APIs
* Configuration objects
* Partial forms

---

## Readonly Modifiers

Mapped types can add `readonly`.

```ts
type ReadonlyType<T> = {
	readonly [K in keyof T]: T[K];
};
```

Example:

```ts
type User = {
	id: number;
	name: string;
};

type ReadonlyUser = ReadonlyType<User>;
```

Now:

```ts
const user: ReadonlyUser = {
	id: 1,
	name: "Satya",
};
```

This is not allowed:

```ts
user.name = "John"; // Error
```

The property is readonly.

---

# Quick Concept Connection

These concepts become easier when we use them together.

Start with a type:

```ts
type User = {
	id: number;
	name: string;
	email: string;
};
```

### 1. `keyof`

Get all keys:

```ts
type UserKey = keyof User;
```

Result:

```ts
"id" | "name" | "email"
```

### 2. Indexed Access

Get the type of a property:

```ts
type UserName = User["name"];
```

Result:

```ts
string
```

### 3. `keyof` + Generic Constraint

Safely access a dynamic property:

```ts
function getProperty<T, K extends keyof T>(
	object: T,
	key: K
): T[K] {
	return object[key];
}
```

### 4. Mapped Type

Transform all properties:

```ts
type Optional<T> = {
	[K in keyof T]?: T[K];
};
```

So the progression is:

```text
keyof
  ↓
Get valid keys

Indexed Access
  ↓
Get property types

keyof + Generics
  ↓
Safely access dynamic properties

Mapped Types
  ↓
Transform existing types
```

# Summary

| Concept               | Purpose                                             |
| --------------------- | --------------------------------------------------- |
| `as`                  | Tell TypeScript to treat a value as a specific type |
| `!`                   | Tell TypeScript a value is not `null`/`undefined`   |
| `keyof`               | Get the keys of a type                              |
| Type-level `typeof`   | Get the type of an existing value                   |
| `keyof typeof`        | Get the keys of an existing object                  |
| Indexed Access `T[K]` | Get the type of a property                          |
| Mapped Types          | Transform properties of an existing type            |

### Most important idea

These features are mainly about **working with existing types dynamically and creating reusable type-safe patterns**.

You don't need to memorize every syntax.

Understand the progression:

```text
Object Type
   ↓
keyof
   ↓
Property Type
   ↓
Dynamic Access
   ↓
Mapped Type
   ↓
Transformed Object Type
```

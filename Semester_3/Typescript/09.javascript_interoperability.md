# JavaScript Interoperability

## 1. JavaScript

TypeScript can work alongside JavaScript. This allows existing JavaScript projects to adopt TypeScript gradually instead of requiring an immediate complete rewrite.

---

## JavaScript Files in Projects

TypeScript can include JavaScript files in a project when JavaScript support is enabled.

A project can contain both:

```text
src/
├── app.ts
├── user.ts
└── legacy.js
```

This allows JavaScript code to be migrated incrementally.

---

## `allowJs`

`allowJs` allows JavaScript files to be included in a TypeScript project.

```json
{
  "compilerOptions": {
    "allowJs": true
  }
}
```

When enabled, `.js` files can participate in the TypeScript project.

---

## `checkJs`

`checkJs` enables type checking for JavaScript files.

```json
{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true
  }
}
```

TypeScript can report type errors in JavaScript files even though those files do not use TypeScript syntax.

---

## JSDoc

JSDoc comments can provide type information in JavaScript files.

```js
/**
 * @param {string} name
 * @returns {string}
 */
function greet(name) {
  return `Hello ${name}`;
}
```

TypeScript can use these annotations for type checking and editor support.

JSDoc is useful when working with JavaScript files that cannot yet be converted to TypeScript.

---

## JavaScript Migration

JavaScript projects can be migrated to TypeScript incrementally.

A common migration can progress through:

```text
JavaScript
    ↓
JavaScript + JSDoc
    ↓
JavaScript + Type Checking
    ↓
TypeScript
```

Individual files can be converted from `.js` to `.ts` as the project progresses.

---

## Gradual Migration

Gradual migration means introducing TypeScript without converting the entire codebase at once.

A project can contain:

- JavaScript files
- TypeScript files
- JavaScript files checked with TypeScript
- Shared types

This approach allows teams to migrate larger codebases over time.

---

## `@ts-check`

`@ts-check` enables TypeScript checking for an individual JavaScript file.

```js
// @ts-check

function greet(name) {
  return `Hello ${name}`;
}
```

It is useful when a project does not globally enable `checkJs` but individual JavaScript files should still receive type checking.

---

# 2. Third-party Libraries

Third-party libraries may provide their own TypeScript declarations or rely on external type definitions.

---

## Typed Packages

Some packages are written in TypeScript and include their own type declarations.

When a package provides its own types, TypeScript can automatically use them when the package is imported.

The package may contain declaration files such as:

```text
index.d.ts
```

or specify its type declarations through its package metadata.

---

## Built-in Type Definitions

Some libraries and JavaScript environments provide TypeScript type definitions directly.

Type definitions describe:

- Functions
- Classes
- Objects
- Properties
- Parameters
- Return values
- Exported members

These definitions allow TypeScript to provide type checking and editor support for the library.

---

## `@types`

The `@types` namespace contains community-maintained type declaration packages.

For a JavaScript package named:

```text
some-library
```

its external type definitions may be available as:

```text
@types/some-library
```

These packages provide `.d.ts` files for libraries that do not include their own types.

---

## DefinitelyTyped

DefinitelyTyped is a large open-source repository containing TypeScript type definitions for many JavaScript libraries.

The packages from DefinitelyTyped are commonly published under the `@types` scope.

For example:

```bash
npm install -D @types/node
```

installs Node.js type definitions.

---

## Libraries Without Types

A JavaScript library may not provide TypeScript declarations.

When TypeScript cannot find types for an imported library, it may report that the module has no declaration file.

The library can still be used, but its type information needs to be provided separately.

---

## Typing Untyped Libraries

An untyped library can be given TypeScript declarations using a custom `.d.ts` file.

For example:

```ts
declare module "legacy-library" {
  export function format(value: string): string;
}
```

The declaration describes the library's public API without changing the library's implementation.

Custom declarations should accurately represent the runtime behavior of the library.

Incorrect declarations can cause TypeScript to accept code that may fail at runtime.

# Contacts (`expo-contacts`)

## What is `expo-contacts`?

`expo-contacts` is an Expo SDK module that allows your React Native application to access the device's contacts.

Using this package, your application can:

- Request permission to access contacts
- Read contacts stored on the device
- Display contact information
- Search contacts
- Add new contacts
- Update existing contacts
- Delete contacts
- Export contacts as a VCF (vCard) file
- Open the native contact editor

It provides a simple API to interact with the phone's contact list without writing any native Android or iOS code.

---

# Why Do We Need Contacts?

Many modern mobile applications interact with the user's contacts to improve the user experience.

Instead of asking users to manually type names and phone numbers, applications can directly access saved contacts (after permission is granted).

Examples:

# Chapter 2 - Installation & Setup

Before we can access the device's contacts, we need to install the **expo-contacts** package and understand how to configure it.

---

# Step 1 - Install Expo Contacts

Install the official Expo Contacts package.

```bash
npx expo install expo-contacts
```

Why do we use `expo install` instead of `npm install`?

Because Expo installs the version that is compatible with your current Expo SDK.

Example:

```bash
npx expo install expo-contacts
```

instead of

```bash
npm install expo-contacts
```

This avoids version compatibility issues.

---

# Step 2 - Import the Package

Import the package into your component.

```js
import * as Contacts from "expo-contacts";
```

---

# Why Do We Use `* as Contacts`?

The package exports many functions.

Instead of importing them one by one, we import everything as **Contacts**.

For example:

```js
Contacts.requestPermissionsAsync();

Contacts.getContactsAsync();

Contacts.addContactAsync();

Contacts.updateContactAsync();

Contacts.removeContactAsync();

Contacts.presentFormAsync();

Contacts.writeContactToFileAsync();
```

Using:

```js
import * as Contacts from "expo-contacts";
```

keeps the code clean and organized.

# Function Used

Expo provides the following function:

```js
Contacts.requestPermissionsAsync()
```

This function displays the system permission dialog.

Example:

```

Allow

Don't Allow
```

The function waits for the user's response and returns a **Permission Object**.


Since the user takes time to respond,

```jsx
import { View, Button, Alert } from "react-native";
import * as Contacts from "expo-contacts";

        await Contacts.requestPermissionsAsync();

          "Success",
          "Permission Granted"

    } catch (error) {

    }

        alignItems:"center"

      />

    </View>

  );

}
```

# Checking Existing Permission

Instead of requesting permission every time,

we can first check the existing permission.

```jsx
const permission =
  await Contacts.getPermissionsAsync();

console.log(permission);
```

If permission is already granted,

there is no need to display the popup again.

Example:

```jsx
const permission =
  await Contacts.getPermissionsAsync();

if (permission.granted) {

  console.log("Already Granted");

} else {

  await Contacts.requestPermissionsAsync();

}
```

This is the recommended approach in production applications.

# Display Contact Names

```jsx
import { useState } from "react";
import { View, Button, Text } from "react-native";
import * as Contacts from "expo-contacts";

export default function App() {

  const [contacts, setContacts] = useState([]);

  const loadContacts = async () => {

    const permission =
      await Contacts.requestPermissionsAsync();

    if (!permission.granted) return;

    const { data } =
      await Contacts.getContactsAsync();

    setContacts(data);

  };

  return (

    <View
      style={{
        flex:1,
        justifyContent:"center",
        alignItems:"center",
        gap:10
      }}
    >

      <Button
        title="Load Contacts"
        onPress={loadContacts}
      />

      {contacts.map((contact) => (

        <Text key={contact.id}>
          {contact.name}
        </Text>

      ))}

    </View>

  );

}
```

# Using FlatList

When displaying many contacts,

`FlatList` is the recommended approach.

```jsx
<FlatList
  data={contacts}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => (
    <Text>{item.name}</Text>
  )}
/>
```

`FlatList` is faster and more memory-efficient than using `map()` for large lists.

Notice the use of:

```js

```

It prevents errors if a property doesn't exist.

---

# Why Use Optional Chaining?

Suppose a contact doesn't have an email.

 Wrong

```js
contact.emails[0].email
```

This may throw an error.

 Correct

```js
contact.emails?.[0]?.email
```

If the email doesn't exist,

the result is simply:

```js
undefined
```

instead of crashing the application.

# Chapter 7 - Sorting Contacts (`Contacts.SortTypes`)

In the previous chapter, we learned how to request specific contact fields using:

```js
Contacts.Fields
```

Now let's learn how to control the **order in which contacts are returned**.

Expo provides:

```js
Contacts.SortTypes
```

Sorting makes it easier for users to find contacts quickly.

---

# Why Do We Need Sorting?

Imagine your phone has 2,000 contacts.

Without sorting:

```
Rahul

Amit

Zoya

Ankit

Riya

Deepak
```

Finding a contact becomes difficult.

Instead, we sort them alphabetically.

```
Amit

Ankit

Deepak

Rahul

Riya

Zoya
```

This provides a much better user experience.

---

# What is `Contacts.SortTypes`?

`Contacts.SortTypes` tells Expo how contacts should be sorted before returning them.

Instead of manually sorting the array yourself,

Expo can return the contacts in the desired order.

---

# Syntax

```js
const { data } =
  await Contacts.getContactsAsync({

    sort:
      Contacts.SortTypes.FirstName,

});
```

---

# Basic Flow

```
Device Contacts

↓

Sort Option

↓

Expo Sorts Contacts

↓

Returns Sorted List
```

---

# Available Sort Types

Expo provides the following sorting options:

```js
Contacts.SortTypes.FirstName

Contacts.SortTypes.LastName

Contacts.SortTypes.UserDefault
```

Let's understand each one.

---

# Contacts.SortTypes.FirstName

```js
Contacts.SortTypes.FirstName
```

Sorts contacts alphabetically using the **first name**.

Example:

Before

```
Rahul Sharma

Amit Kumar

Deepak Singh

Ankit Verma
```

After

```
Amit Kumar

Ankit Verma

Deepak Singh

Rahul Sharma
```

---

# Example

```jsx
const { data } =
  await Contacts.getContactsAsync({

    sort:
      Contacts.SortTypes.FirstName,

});
```

---

# Contacts.SortTypes.LastName

```js
Contacts.SortTypes.LastName
```

Sorts contacts alphabetically using the **last name**.

Example:

Before

```
Rahul Sharma

Amit Kumar

Deepak Singh

Ankit Verma
```

After

```
Amit Kumar

Rahul Sharma

Deepak Singh

Ankit Verma
```

Because:

```
Kumar

↓

Sharma

↓

Singh

↓

Verma
```

---

# Example

```jsx
const { data } =
  await Contacts.getContactsAsync({

    sort:
      Contacts.SortTypes.LastName,

});
```

# Contacts.SortTypes.UserDefault

```js
Contacts.SortTypes.UserDefault
```

Uses the sorting preference configured by the user on their device.

Example:

Some users prefer:

```

```

Some users prefer:

```

```

Instead of forcing a sorting method,

Expo follows the user's system preference.

# Example


### Messaging Apps

Examples:

- WhatsApp
- Telegram

Usually use:



### Personal Contact Apps


Yes.

You can fetch contacts again using a different sorting option.

Example:

```jsx

  await Contacts.getContactsAsync({
```

or


If you don't specify the `sort` option,

Example:

```jsx

  await Contacts.getContactsAsync();
```

The order may vary between Android and iOS.

If your app requires a consistent order, always specify a sorting option.

- User's Contact Settings

Using:

# Chapter 8 - Displaying Contacts Using `FlatList`

In the previous chapter, we learned how to sort contacts using:

Almost every contact-based application displays contacts in a scrollable list.

We'll build a similar contact list using React Native's `FlatList`.

---

# Why Use FlatList?

Imagine your device has:

```
10 Contacts
```

Using:

```jsx
contacts.map(...)
```

works fine.

But what if the device has:

```
5,000 Contacts
```

Rendering all contacts at once can slow down your application.

Instead, React Native provides:

```jsx
<FlatList />
```

FlatList renders only the visible items.

Benefits:

- Better Performance
- Less Memory Usage
- Smooth Scrolling
- Recommended for Large Lists

---

# Basic Flow

```
Read Contacts

↓

Store in State

↓

Pass Data to FlatList

↓

Render Contact Card
```

---

# First Example

```jsx
import { useState } from "react";
import {
  View,
  Button,
  FlatList,
  Text,
} from "react-native";
import * as Contacts from "expo-contacts";

export default function App() {

  const [contacts, setContacts] = useState([]);

  const loadContacts = async () => {

    const permission =
      await Contacts.requestPermissionsAsync();

    if (!permission.granted) return;

    const { data } =
      await Contacts.getContactsAsync({

        fields: [
          Contacts.Fields.Name,
          Contacts.Fields.PhoneNumbers,
        ],

      });

    setContacts(data);

  };

  return (

    <View style={{ flex: 1 }}>

      <Button
        title="Load Contacts"
        onPress={loadContacts}
      />

      <FlatList
        data={contacts}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => (
          <Text
            style={{
              fontSize:18,
              padding:15
            }}
          >
            {item.name}
          </Text>
        )}
      />

    </View>

  );

}
```

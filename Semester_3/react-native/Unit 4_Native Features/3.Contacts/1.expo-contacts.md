# Module 1 - Introduction to Expo Contacts (`expo-contacts`)

## What is `expo-contacts`?

`expo-contacts` is an Expo SDK module that allows your React Native application to access the device's contacts.

Using this package, your application can:

- Request permission to access contacts
- Read contacts stored on the device
- Display contact information
- Search contacts
- Add new contacts
- Update existing contacts
- Delete contacts
- Export contacts as a VCF (vCard) file
- Open the native contact editor

It provides a simple API to interact with the phone's contact list without writing any native Android or iOS code.

---

# Chapter 2 - Installation & Setup

Before we can access the device's contacts, we need to install the **expo-contacts** package and understand how to configure it.

---

# Step 1 - Install Expo Contacts

Install the official Expo Contacts package.

```bash
npx expo install expo-contacts
```

Why do we use `expo install` instead of `npm install`?

Because Expo installs the version that is compatible with your current Expo SDK.

Example:

```bash
npx expo install expo-contacts
```

instead of

```bash
npm install expo-contacts
```

This avoids version compatibility issues.

---

# Step 2 - Import the Package

Import the package into your component.

```js
import * as Contacts from "expo-contacts";
```

---

# Why Do We Use `* as Contacts`?

The package exports many functions.

Instead of importing them one by one, we import everything as **Contacts**.

For example:

```js
Contacts.requestPermissionsAsync();

Contacts.getContactsAsync();

Contacts.addContactAsync();

Contacts.updateContactAsync();

Contacts.removeContactAsync();

Contacts.presentFormAsync();

Contacts.writeContactToFileAsync();
```

Using:

```js
import * as Contacts from "expo-contacts";
```

keeps the code clean and organized.

# Check Existing Permission

Before requesting permission, we can check whether the permission has already been granted.

Expo provides:

```js
Contacts.getPermissionsAsync()
```

Example:

```js
const permission =
  await Contacts.getPermissionsAsync();

console.log(permission);
```

This function **does not show the permission popup**.

It simply returns the current permission status.

---

# Why Check Permission First?

Imagine this situation.

```
User Opens App

↓

Permission Already Granted

↓

App Shows Popup Again
```

This creates a poor user experience.

Instead, production apps follow this flow.

```
App Starts

↓

Check Existing Permission

↓

Already Granted

↓

Load Contacts

↓

Else

↓

Request Permission
```

This avoids showing unnecessary permission dialogs.

# Chapter 3 - Request Contact Permission

Before reading the user's contacts, we must first request permission.

Without permission, Expo cannot access the device's contact list.

This is the first step every contact-based application performs.

---

# What is Contact Permission?

Contact Permission allows your application to access the contacts stored on the user's device.

For example:

- WhatsApp
- Google Contacts
- Truecaller
- Phone Dialer
- Telegram

All these applications ask for contact permission before displaying your contacts.

---

# Function Used

Expo provides the following function:

```js
Contacts.requestPermissionsAsync()
```

This function displays the system permission dialog.

Example:

```
Allow "Expo Go"
to access your contacts?

Allow

Don't Allow
```

The function waits for the user's response and returns a **Permission Object**.

---

# Syntax

```js
const permission =
  await Contacts.requestPermissionsAsync();
```

Since the user takes time to respond,

this function returns a **Promise**.

That's why we use:

```js
await
```

---

# Returned Object

Example:

```js
{
  status: "granted",
  granted: true,
  canAskAgain: true,
  expires: "never"
}
```

---

# Understanding Every Property

## status

Shows the current permission status.

Possible values:

```text
granted

denied

undetermined
```

---

### granted

The user allowed contact access.

```
Contact Permission Granted
```

---

### denied

The user denied permission.

```
Contact Permission Denied
```

---

### undetermined

The user has not responded yet.

```
Permission Not Requested Yet
```

---

## granted

Returns:

```js
true
```

or

```js
false
```

Example:

```js
if (permission.granted) {

  console.log("Permission Granted");

}
```

---

## canAskAgain

Indicates whether the permission popup can be shown again.

Example:

```js
true
```

You can ask again.

Example:

```js
false
```

The user selected:

```
Don't Ask Again
```

Now the application should guide the user to enable permission from the device settings.

---

## expires

Usually returns:

```text
never
```

Meaning the permission does not expire automatically.

# Example 1 - Request Permission

```jsx
import { View, Button } from "react-native";
import * as Contacts from "expo-contacts";

export default function App() {

  const requestPermission = async () => {

    const permission =
      await Contacts.requestPermissionsAsync();

    console.log(permission);

  };

  return (

    <View
      style={{
        flex:1,
        justifyContent:"center",
        alignItems:"center"
      }}
    >

      <Button
        title="Request Contact Permission"
        onPress={requestPermission}
      />

    </View>

  );

}
```

# Example 2 - Check Permission Status

Instead of printing the complete object,

we can check only the status.

```jsx
const requestPermission = async () => {

  const permission =
    await Contacts.requestPermissionsAsync();

  if (permission.status === "granted") {

    console.log("Permission Granted");

  } else {

    console.log("Permission Denied");

  }

};
```

# Better Approach

Expo also provides the `granted` property.

Instead of comparing strings,

we can simply write:

```jsx
const requestPermission = async () => {

  const permission =
    await Contacts.requestPermissionsAsync();

  if (permission.granted) {

    console.log("Permission Granted");

  } else {

    console.log("Permission Denied");

  }

};
```

This approach is shorter and easier to read.

# Complete Example

```jsx
import { View, Button, Alert } from "react-native";
import * as Contacts from "expo-contacts";

export default function App() {

  const requestPermission = async () => {

    try {

      const permission =
        await Contacts.requestPermissionsAsync();

      if (permission.granted) {

        Alert.alert(
          "Success",
          "Permission Granted"
        );

      } else {

        Alert.alert(
          "Permission Denied",
          "Contacts permission is required to continue."
        );

      }

    } catch (error) {

      console.log(error);

    }

  };

  return (

    <View
      style={{
        flex:1,
        justifyContent:"center",
        alignItems:"center"
      }}
    >

      <Button
        title="Request Contact Permission"
        onPress={requestPermission}
      />

    </View>

  );

}
```

# Checking Existing Permission

Instead of requesting permission every time,

we can first check the existing permission.

```jsx
const permission =
  await Contacts.getPermissionsAsync();

console.log(permission);
```

If permission is already granted,

there is no need to display the popup again.

Example:

```jsx
const permission =
  await Contacts.getPermissionsAsync();

if (permission.granted) {

  console.log("Already Granted");

} else {

  await Contacts.requestPermissionsAsync();

}
```

This is the recommended approach in production applications.

---

# Error Handling

Always wrap permission requests inside `try...catch`.

```jsx
try {

  const permission =
    await Contacts.requestPermissionsAsync();

  console.log(permission);

} catch (error) {

  console.log(error);

}
```

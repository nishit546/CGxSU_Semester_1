# Expo File System — Assignment 1: Storage Inspector

## Overview

Build a React Native screen using Expo's `expo-file-system` modern API. The screen should help users understand where application files are stored and how much device storage is available.

## Learning Objectives

By completing this assignment, students will practice:

- Using `Paths` to inspect application storage locations.
- Distinguishing document, cache, and bundled asset locations.
- Displaying storage values in readable GB units.
- Explaining the difference between a path, URI, file, and directory.
- Building a clear UI with React Native components.

## Requirements

### 1. Display Storage Locations

Show the URI for each of the following:

- `Paths.document.uri`
- `Paths.cache.uri`
- `Paths.bundle.uri`

Each location must have a clear label and its URI should be readable (use wrapping or a suitable layout for long values).

### 2. Display Device Storage Information

Display:

- Total internal disk space.
- Available internal disk space.
- Used storage, calculated as `total - available`.

Convert byte values to GB and format them to two decimal places.

### 3. Explain Each Location

Add a short description for each location:

| Location | Description |
|---|---|
| Document | Files the application intends to keep available |
| Cache | Temporary or recreatable files; do not assume they will remain indefinitely |
| Bundle | Resources included with the application |

### 4. UI and Usability

The screen should include:

- A title: **Expo File System — Storage Inspector**
- Separate cards or sections for locations and storage information.
- Clear labels and readable values.
- A refresh button that updates the displayed storage information.
- A loading or refreshing state if needed.
- A friendly error message if information cannot be displayed.

## Technical Constraints

- Use the modern API imported from `expo-file-system`.
- Do not hard-code Android or iOS physical paths.
- Do not treat `Paths.document`, `Paths.cache`, or `Paths.bundle` as arbitrary strings; use their documented properties.
- Keep the storage calculation and formatting logic separate from the JSX where practical.
- Do not claim that cache files are guaranteed to persist.

## Starter Guidance

Begin with:

```tsx
import { View, Text, Button } from "react-native";
import { Paths } from "expo-file-system";
```

Use the following conversion:

```tsx
const bytesToGB = (bytes: number) => bytes / 1024 ** 3;
```

Use `.toFixed(2)` to display two decimal places.

## Deliverables

1. A working Expo application screen.
2. A screenshot showing the locations and storage values.
3. A short README section explaining:
   - What `Paths` does.
   - The difference between document, cache, and bundle.
   - Why physical device paths should not be hard-coded.
   - How used storage is calculated.


## Bonus Challenges

- Show used storage as a percentage of total storage.
- Add a progress bar representing used versus available storage.
- Add a copy-URI button for each location.
- Explain why the same file extension can belong in either document or cache storage.

# Expo File System — Assignment 2: Local Notes Manager

## Overview

Build a local Notes application that stores notes as text files using Expo's `expo-file-system` modern API.

The application must let users create, save, list, read, update, and delete notes stored in the application's document directory.

## Learning Objectives

By completing this assignment, students will practice:

- Using `Paths` to choose a persistent application location.
- Creating and working with `Directory` and `File` references.
- Understanding that constructing a `File` reference does not itself guarantee that the physical file exists.
- Creating directories and files explicitly.
- Reading and writing text.
- Listing directory contents and refreshing UI state.
- Handling missing files and invalid input.

## Scenario

You are building a simple offline notes application. A user should be able to save a note and open it again after navigating away from the screen or restarting the application.

Suggested storage structure:

```text
Document Directory/
└── notes/
    ├── note-1.txt
    ├── note-2.txt
    └── note-3.txt
```

## Required Features

### 1. Initialize the Notes Directory

- Create a `notes` directory inside `Paths.document`.
- Ensure the directory exists before attempting to save or list notes.
- Use appropriate creation options when setup may run more than once.

### 2. Create a Note

Provide:

- A text input for the note title.
- A multiline text input for note content.
- A Save button.

Requirements:

- Do not allow an empty title or empty content.
- Generate a safe, unique filename (for example, using a generated ID or timestamp).
- Save the note as a `.txt` file.
- Show a success or error message.

### 3. List Saved Notes

- Read the contents of the notes directory.
- Display saved note files in a list.
- Show each note's filename or a friendly title.
- Include a Refresh button to reload the directory contents.
- Display an empty state when no notes exist.

### 4. Read and Open a Note

When a user selects a note:

- Read its text content from the file.
- Display the content in the editor or a detail section.
- Handle the case where the selected file no longer exists.

### 5. Update a Note

- Allow the user to edit the selected note.
- Save the updated content to the same file.
- Confirm that the update succeeded.
- Refresh the list if the filename or displayed metadata changes.

### 6. Delete a Note

- Provide a Delete action for a selected note.
- Ask for confirmation before deleting.
- Remove the file using the appropriate File System operation.
- Clear the editor if the deleted note was open.
- Refresh the list after deletion.

## Technical Requirements

- Use `File`, `Directory`, and `Paths` from `expo-file-system`.
- Store user-created notes in `Paths.document`, not the cache directory.
- Use the current modern API methods covered in the course material.
- Keep file-system operations in helper functions or a small service module where practical.
- Use React state to keep the visible list and editor synchronized with file operations.
- Handle errors such as missing files, empty input, and failed read/write/delete operations.
- Avoid hard-coded platform-specific storage paths.

## Suggested Function Breakdown

Students may organize their logic using functions such as:

```text
ensureNotesDirectory()
loadNotes()
createNote()
openNote()
updateNote()
deleteNote()
refreshNotes()
```

These are suggested application-level function names, not required Expo API names.

          ↓

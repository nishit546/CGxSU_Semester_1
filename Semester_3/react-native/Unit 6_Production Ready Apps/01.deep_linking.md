
# React Native – Deep Linking

> Learn how to implement Deep Linking in **React Native with Expo SDK 54**. By the end of this module, you'll be able to open specific screens in your app directly from URLs, QR codes, emails, notifications, and other applications.

---

## Overview

Deep Linking allows users to open a specific screen inside your mobile application directly from an external source, rather than always starting at the home screen.

For example, imagine a shopping application. A user receives a promotional email containing a link to a product. Instead of opening the app's home page, tapping the link opens the exact product page.

This creates a seamless user experience and is used in almost every production application.

In this module, you'll learn how Deep Linking works in **Expo SDK 54**, how to configure it with **Expo Router**, how URL routing works inside the **`app` directory**, and how to handle dynamic routes and parameters.

---

## What is Deep Linking?

**Normal App Launch:**
```
Open App
↓
Home Screen
```

**With Deep Linking:**
```
Tap URL / QR Code / Notification
↓
Open App
↓
Specific Screen (Product, Profile, Settings, etc.)
```

Instead of always opening the first screen, the application opens the exact page mentioned in the URL.

**Real-life Analogy**:  
Deep Linking is like having a VIP entrance. Instead of entering through the main door and walking to a specific room, you get a direct pass that takes you straight to the room you want.

### **Real-World Examples**

| App          | Deep Link Example                  | What Happens |
|--------------|------------------------------------|--------------|
| Instagram    | `instagram://user/cristiano`      | Opens Cristiano’s profile |
| Amazon       | `amazon://product/12345`          | Opens product page |
| YouTube      | `youtube://watch?v=abc123`        | Opens specific video |
| WhatsApp     | `https://wa.me/919999999999`      | Opens chat with number |
| Swiggy       | `swiggy://restaurant/452`         | Opens restaurant page |

**Without Deep Linking:**
```
User clicks Product Link

```

**With Deep Linking:**
```
User clicks Product Link
```

**Benefits:**

- Supports QR codes, push notifications, emails, SMS

## How Deep Linking Works

```
URL
|
v
Operating System
|
v
Your App
|
v
Expo Router
|
v
Correct Screen Opens
```

The operating system recognizes that your app can handle a specific URL scheme and launches it. Expo Router then matches the URL to the appropriate file inside the `app` directory and opens the correct screen.

---

## Expo Router and File-Based Routing

In Expo Router, every file inside the `app` directory represents a route.

**Example Structure:**

```
app/
|
|-- index.tsx
|-- profile.tsx
|-- settings.tsx
|-- products/
|   |-- [id].tsx
```

**Corresponding Routes:**

| File Path              | URL Route          | Screen Opened     |
|------------------------|--------------------|-------------------|
| `app/index.tsx`        | `/`                | Home              |
| `app/profile.tsx`      | `/profile`         | Profile           |
| `app/settings.tsx`     | `/settings`        | Settings          |
| `app/products/[id].tsx`| `/products/15`     | Product Details   |

Dynamic routes use square brackets (`[id]`) to capture URL parameters.

## URL Scheme

A URL scheme tells the operating system how to launch your application.

**Example:**
```
myapp://profile
```

- `myapp` = Scheme (defined in app configuration)
- `profile` = Path / Screen

In Expo projects, the scheme is defined in `app.json` or `app.config.ts`.

**Configuration Example (`app.json`):**

```json
{
  "expo": {
    "name": "MyApp",
    "slug": "myapp",
    "scheme": "myapp",
    "version": "1.0.0",
    "orientation": "portrait",
    "platforms": ["ios", "android"]
  }
}
```

After setting the scheme, you can use links like:

```
myapp://
myapp://explore
myapp://profile
myapp://product/101
```

## Passing Parameters

URLs can contain dynamic parameters.

**Example:**
```
myapp://product/101
```

Here, `101` is the Product ID.

The destination screen (`app/product/[id].tsx`) can read this value using:

```tsx
import { useLocalSearchParams } from 'expo-router';

export default function ProductScreen() {
  const { id } = useLocalSearchParams();

  return (
    // Use the id to fetch product details
  );
}
```

---

## Query Parameters

URLs can also contain query parameters.

**Example:**
```
myapp://search?category=mobile&sort=price
```

- `category` = mobile
- `sort` = price

You can read them the same way:

```tsx
const { category, sort } = useLocalSearchParams();
```

## Deep Linking with Tabs

Deep links can open a specific tab directly.

**Examples:**

```
myapp://explore
```
Opens the Explore Tab.

```
myapp://profile
```
Opens the Profile Tab.

```
myapp://
```
Opens the Home Tab (default).

Because of the `(tabs)` group in Expo Router, the tab navigator automatically selects the correct tab based on the URL path.

## Deep Linking with Dynamic Routes

Dynamic routes are created using square brackets in the file name.

**Folder Structure:**
```
app/
|-- product/
|   |-- [id].tsx
```

**URL Example:**
```
myapp://product/55
```

**What Happens:**
1. App opens
2. Expo Router matches the path `/product/55`
3. It loads the file `app/product/[id].tsx`
4. The value `55` is passed as the parameter `id`

**Code Example (`app/product/[id].tsx`):**

```tsx
import { View, Text, StyleSheet } from 'react-native';
import { useLocalSearchParams } from 'expo-router';

export default function ProductScreen() {
  const { id } = useLocalSearchParams<{ id: string }>();

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Product Details</Text>
      <Text style={styles.id}>Product ID: {id}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
    padding: 20,
  },
  title: {
    fontSize: 24,
    fontWeight: 'bold',
    marginBottom: 12,
  },
  id: {
    fontSize: 18,
    color: '#555',
  },
});
```

This pattern is commonly used for:
- Product details
- User profiles
- Blog posts
- Order details
- Any content that has a unique ID

## Configuring Deep Linking in Expo SDK 54

### Step 1: Set the Scheme

Open `app.json` (or `app.config.ts`) and add a scheme:

```json
{
  "expo": {
    "name": "MyApp",
    "slug": "myapp",
    "scheme": "myapp",
    "version": "1.0.0",
    "orientation": "portrait",
    "icon": "./assets/images/icon.png",
    "userInterfaceStyle": "light",
    "splash": {
      "image": "./assets/images/splash-icon.png",
      "resizeMode": "contain",
      "backgroundColor": "#ffffff"
    },
    "ios": {
      "supportsTablet": true,
      "bundleIdentifier": "com.yourcompany.myapp"
    },
    "android": {
      "adaptiveIcon": {
        "foregroundImage": "./assets/images/adaptive-icon.png",
        "backgroundColor": "#ffffff"
      },
      "package": "com.yourcompany.myapp"
    }
  }
}
```

### Step 2: Restart the Development Server

After changing the scheme, restart Expo:

```bash
npx expo start --clear
```

## Testing Deep Links

### Testing on Android

You can test deep links using ADB:

```bash
adb shell am start -a android.intent.action.VIEW -d "myapp://product/101"
```

Or:

```bash
npx uri-scheme open "myapp://product/101" --android
```

### Testing on iOS

```bash
npx uri-scheme open "myapp://product/101" --ios
```

You can also type the URL in Safari (on a real device or simulator) and it will prompt to open the app.

### Testing with Expo Go

Expo Go uses a different scheme. For development builds or production apps, use your custom scheme (`myapp://`).

For Expo Go testing, use:

```
exp://127.0.0.1:8081/--/product/101
```

## Handling Invalid or Unknown Links

If a user opens a link that does not match any route, Expo Router will show a "Not Found" screen by default.

You can create a custom not-found page:

```
app/
|-- +not-found.tsx
```

Example:

```tsx
import { View, Text, StyleSheet } from 'react-native';
import { Link } from 'expo-router';

export default function NotFoundScreen() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Page Not Found</Text>
      <Link href="/">Go back to Home</Link>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
  },
  title: {
    fontSize: 22,
    fontWeight: 'bold',
    marginBottom: 16,
  },
});
```

## Universal Links (iOS) and App Links (Android)

Custom schemes (`myapp://`) work well, but they have one limitation: if the app is not installed, the link does nothing useful.

**Universal Links (iOS)** and **App Links (Android)** solve this problem by using regular `https://` links.

Example:
```
https://myapp.com/product/101
```

- If the app is installed: Opens the Product screen directly
- If the app is not installed: Opens the website (or App Store / Play Store)

This is the recommended approach for production apps.

### Configuration Overview

**1. Domain Ownership**
You must own a domain (example: `myapp.com`).

**2. Android - assetlinks.json**
Place this file on your server:
```
https://myapp.com/.well-known/assetlinks.json
```

**3. iOS - apple-app-site-association**
Place this file on your server:
```
https://myapp.com/.well-known/apple-app-site-association
```

**4. Update app.json**
```json
{
  "expo": {
    "scheme": "myapp",
    "ios": {
      "associatedDomains": ["applinks:myapp.com"]
    },
    "android": {
      "intentFilters": [
        {
          "action": "VIEW",
          "autoVerify": true,
          "data": [
            {
              "scheme": "https",
              "host": "myapp.com",
              "pathPrefix": "/"
            }
          ],
          "category": ["BROWSABLE", "DEFAULT"]
        }
      ]
    }
  }
}
```

## Best Practices

| Practice                              | Reason                                      |
|---------------------------------------|---------------------------------------------|
| Prefer HTTPS Universal/App Links      | Better user experience when app is not installed |
| Keep URL structure clean              | Easy to understand and share                |
| Use dynamic routes for content        | Product, User, Order pages                  |
| Handle not-found cases                | Prevent blank screens                       |
| Test on real devices                  | Simulators can behave differently           |
| Support both custom scheme and HTTPS  | Maximum compatibility                       |
| Avoid deep nesting in URLs            | Keep paths short and clear                  |


# React Native – Debugging

Debugging is the process of finding, analyzing, and fixing issues in a React Native application. Efficient debugging is one of the most important skills for building stable and high-quality mobile apps.

---

## 1. What is Debugging?

Debugging is the process of identifying, analyzing, and fixing bugs in an application.

**Common issues you will face:**
- App crashes
- API failures
- UI rendering issues
- State management bugs
- Performance problems
- Memory leaks
- Navigation errors
- Unexpected behavior on real devices

**Real-life Analogy**:
Debugging is like being a detective. You gather clues (logs, errors, network responses), form theories, and systematically eliminate possibilities until you find the root cause.

## 2. Console Debugging

The simplest and most widely used debugging method.

```jsx
console.log("User Loaded");
console.warn("Invalid Email");
console.error("API Failed");
```

### Console Methods

| Method            | Purpose                              | When to Use |
|-------------------|--------------------------------------|-------------|
| `console.log()`   | General information                  | Normal flow |
| `console.warn()`  | Potential issues                     | Non-critical warnings |
| `console.error()` | Errors and failures                  | Exceptions |
| `console.table()` | Display arrays and objects clearly   | Large data |
| `console.time()`  | Start performance timer              | Measure speed |
| `console.timeEnd()` | Stop timer and show duration       | Performance checks |

**Example – Measuring API Time:**

```jsx
console.time("FetchUsers");
const response = await fetchUsers();
console.timeEnd("FetchUsers");
```

**Better Logging Practice:**

```jsx
console.log("User Data:", user);
console.log("API Response Status:", response.status);
console.error("Login Failed:", error.message);
```

## 3. LogBox

React Native provides **LogBox** to display warnings and errors in a more organized way during development.

LogBox appears as a yellow or red box at the bottom of the screen when something goes wrong.

### Common LogBox Warnings

```
VirtualizedLists should never be nested inside plain ScrollViews...
```

```
Warning: Each child in a list should have a unique "key" prop.
```

```
Require cycle: ...
```

### How to Ignore Specific Warnings (Development Only)

```jsx
import { LogBox } from "react-native";

LogBox.ignoreLogs([
  "VirtualizedLists should never be nested",
  "Non-serializable values were found in the navigation state",
]);
```

### Hide All Logs (Not Recommended)

```jsx
LogBox.ignoreAllLogs();
```

**Important Notes:**
- Ignoring warnings should only be done during development
- Never ignore important warnings in production
- Fix the root cause whenever possible instead of hiding the message

### Best Practice

Only ignore warnings that you fully understand and have decided are safe to suppress. Always prefer fixing the issue.

## 4. React DevTools

React DevTools is a powerful tool that helps you inspect the React component tree.

### Features

- View the full Component Tree
- Inspect Props
- Inspect State
- Inspect Hooks
- View Context values
- Track component re-renders
- Highlight updates

### How to Open React DevTools

**Method 1 – From Expo / React Native:**
- Shake the device or press `j` in the Metro terminal
- Select "Open React DevTools"

**Method 2 – Standalone App:**
```bash
npx react-devtools
```

### Benefits

- Understand component hierarchy easily
- Detect unnecessary re-renders
- Debug props and state issues
- See which component is causing problems

### Common Use Cases

- Finding why a component is re-rendering too often
- Checking if correct props are being passed
- Inspecting complex nested components
- Debugging Context values

## 5. Flipper

Flipper is the official debugging platform for React Native. It provides a desktop application that connects to your running app and gives you powerful inspection tools.

### Main Features

- Network Inspector
- Layout Inspector
- Logs Viewer
- Database Viewer
- Crash Reporter
- Performance Tools
- React DevTools integration
- Image inspection
- Shared Preferences / AsyncStorage viewer

### Common Plugins

| Plugin              | Purpose                              |
|---------------------|--------------------------------------|
| React DevTools      | Inspect components, props, state     |
| Network             | Monitor API calls and responses      |
| Layout              | Inspect native view hierarchy        |
| Metro Logs          | View console logs                    |
| Images              | Inspect loaded images                |
| Shared Preferences  | View stored data                     |

### How to Use Flipper

1. Download and install Flipper from the official website
2. Start your React Native / Expo app
3. Open Flipper
4. Select your running device or emulator
5. Use the available plugins

### Common Use Cases

- Debugging API requests and responses
- Checking request headers and status codes
- Analyzing performance
- Inspecting layout issues
- Viewing stored data
- Tracking crashes

### Network Debugging Example

When you make an API call, Flipper shows:
- Request URL
- Request headers
- Request body
- Response status
- Response body
- Time taken

This is extremely useful when debugging authentication, failed requests, or incorrect data.

## 6. VS Code Debugging

You can debug React Native applications directly from Visual Studio Code using breakpoints.

### Features

- Breakpoints
- Step Over
- Step Into
- Step Out
- Call Stack
- Variables inspection
- Watch expressions
- Debug console

### How Breakpoints Work

```
Click on the left margin of a line
|
v
Breakpoint is added (red dot)
|
v
Start the debugger
|
v
Execution pauses at the breakpoint
|
v
Inspect variables and step through code
```

### Benefits

- Much more powerful than console.log
- Inspect variable values at runtime
- Understand the exact flow of execution
- Faster root cause detection

### Tips for VS Code Debugging

- Use conditional breakpoints when needed
- Combine with React DevTools for better results
- Debug both JavaScript and native side when required
- Use the Debug Console to evaluate expressions

## 7. Hermes Debugging

Hermes is the default JavaScript engine used by React Native (and Expo).

### Benefits of Hermes

- Faster app startup
- Lower memory usage
- Better performance
- Improved debugging support
- Smaller app size (in many cases)

### Common Debugging Areas with Hermes

- JavaScript exceptions
- Memory usage
- Performance bottlenecks
- Startup time
- Garbage collection issues

### Enabling Hermes

In most modern Expo and React Native projects, Hermes is already enabled by default.

You can confirm it in `app.json` or `app.config.js`:

```json
{
  "expo": {
    "jsEngine": "hermes"
  }
}
```

### Debugging Tips with Hermes

- Use Flipper + Hermes for better performance insights
- Monitor memory usage on real devices
- Watch for long-running JavaScript tasks that block the UI thread
- Prefer `useNativeDriver` and Reanimated for animations

## 8. Debugging API Calls

API-related bugs are very common. Always inspect the request and response carefully.

### Basic Pattern

```jsx
try {
  const response = await axios.get("/users");
  console.log("Status:", response.status);
  console.log("Data:", response.data);
} catch (error) {
  console.error("API Error:", error.message);

  if (error.response) {
    console.error("Status Code:", error.response.status);
    console.error("Error Data:", error.response.data);
  } else if (error.request) {
    console.error("No response received");
  }
}
```

### What You Should Always Log

- Request URL
- Request payload
- Response status code
- Response data
- Error message
- Network connectivity issues

### Recommended Approach

Use the Network plugin in Flipper together with proper try/catch blocks. This combination makes API debugging much faster and more reliable.

## 9. Debugging Performance

Common performance issues include:

- Slow rendering
- Memory leaks
- Unnecessary re-renders
- Large images
- Heavy lists without optimization
- Blocking the JavaScript thread

### Useful Tools

| Tool                  | Purpose                              |
|-----------------------|--------------------------------------|
| Flipper               | Network + Performance + Layout       |
| React DevTools        | Detect re-renders                    |
| Hermes                | Memory and engine performance        |
| Performance Monitor   | FPS and memory (shake device)        |

### Quick Performance Tips

- Use `React.memo`, `useMemo`, and `useCallback` wisely
- Prefer `FlashList` over `FlatList` for long lists
- Optimize images
- Avoid anonymous functions in render
- Profile before optimizing

---

## 10. Debugging Checklist

Use this checklist whenever you face a bug:

- Check the Console for errors and warnings
- Read the full error message carefully
- Verify the API response (status + data)
- Inspect Props and State using React DevTools
- Check if the correct screen is being rendered
- Verify navigation parameters
- Test on a real device (not only emulator)
- Test on both Android and iOS
- Check network connectivity
- Look for recent code changes that might have caused the issue

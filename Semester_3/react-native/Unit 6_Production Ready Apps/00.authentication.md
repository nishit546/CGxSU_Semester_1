
#  React Native – Authentication

> Build a complete and secure authentication system in React Native using JWT, Signup, Login, Refresh Tokens, and production-grade security techniques.

---

##  Overview

Authentication is one of the most critical features of any modern mobile application. Whether you're building a social media app, an e-commerce platform, a banking application, a food delivery service, or an online learning platform, users need a secure way to create an account, sign in, and access protected resources.

In this module, you'll learn how authentication works from the ground up. Rather than simply copying code, you'll understand **why authentication is needed**, **how JWT works internally**, **how access and refresh tokens communicate with the server**, and **how to securely manage user sessions**.

We'll start with the basics of user registration and login before moving into advanced topics like token expiration, automatic token refresh, protected routes, secure storage, and best security practices followed by real-world companies.

By the end of this module, you'll be able to build a complete authentication flow that can be integrated into almost any React Native application.

---

## Why Authentication Matters

Imagine opening Instagram.

- You sign up using your email.
- Next time, you simply log in.
- Your profile appears instantly.
- You don't need to log in every few minutes.
- If your token expires, Instagram silently refreshes it without asking you to log in again.

All of this is possible because of a properly designed authentication system.

**Authentication ensures that:**

- Only registered users can access private data.
- User information remains secure.
- Sessions stay active without frequent logins.
- Sensitive APIs are protected.
- User identity is verified before granting access.

Without authentication, anyone could access another user's personal information.

**Real-life Analogy**:  
Authentication is like a digital ID card + security guard system. Your Access Token is the temporary visitor pass, and the Refresh Token is the long-term membership card that allows you to get a new visitor pass without standing in the queue again.

## 1. JWT (JSON Web Token)

**Description**: JWT is the most widely used authentication mechanism for modern web and mobile applications.

### **What is JWT?**

Instead of storing user sessions on the server (which is hard to scale), the server generates a **signed token** containing user information. The client stores this token and sends it with every protected API request.

JWT is **stateless** — the server does not need to remember who is logged in. It only needs to verify the signature of the token.

### Structure of a JWT

A JWT consists of three parts separated by dots (`.`):

```
Header.Payload.Signature
```

**Example Token:**
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
eyJ1c2VySWQiOjEyMywibmFtZSI6IlJhamVzaCIsImV4cCI6MTcxOTg0ODAwMH0.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

| Part       | Description                                      | Example Content |
|------------|--------------------------------------------------|-----------------|
| **Header** | Algorithm and token type                         | `{ "alg": "HS256", "typ": "JWT" }` |
| **Payload**| User data + expiration time                      | `{ "userId": 123, "name": "Rajesh", "exp": 1719848000 }` |
| **Signature** | Verifies the token is not tampered with       | Created using secret key |

---

### **How JWT Works (Step by Step)**

1. User logs in with email + password
2. Backend verifies credentials
3. Backend creates a JWT containing user info + expiration
4. Backend sends the JWT to the client
5. Client stores the token securely
6. Client sends the token in every protected request:
   ```
   Authorization: Bearer <token>
   ```
7. Backend verifies the signature and expiration
8. If valid → Access is granted

---

### **Access Token vs Refresh Token**

| Token Type       | Lifetime          | Purpose                              | Stored Where? |
|------------------|-------------------|--------------------------------------|---------------|
| **Access Token** | Short (15 min – 1 hour) | Access protected APIs               | SecureStore / Memory |
| **Refresh Token**| Long (7–30 days)  | Get a new Access Token when it expires | SecureStore (more carefully) |

---

### **Basic JWT Example (Frontend Side)**

```jsx
// After successful login
const loginResponse = await axios.post('/api/login', {
  email: 'rajesh@example.com',
  password: 'securePassword123'
});

const { accessToken, refreshToken } = loginResponse.data;

// Store tokens securely (we'll cover SecureStore later)
await SecureStore.setItemAsync('accessToken', accessToken);
await SecureStore.setItemAsync('refreshToken', refreshToken);
```

**Sending Token with Requests:**
```jsx
const response = await axios.get('/api/profile', {
  headers: {
    Authorization: `Bearer ${accessToken}`
  }
});
```

---

### **Important Concepts**

- **Stateless**: Server doesn’t store session data
- **Signed**: Cannot be modified without the secret key
- **Expiration**: Access Tokens should expire quickly
- **Bearer Token**: Standard way to send JWT in headers

## 2. Signup (User Registration)

**Description**: Signup is the process of creating a new user account so the user can later log in and access protected features.

### **What is Signup?**

Before a user can use most applications, they need to create an account. The Signup screen collects necessary information, validates it, and sends it to the backend to create a new user.

A good Signup experience should:
- Be clean and professional
- Validate inputs properly
- Show clear error messages
- Handle loading and success/error states
- Prevent common mistakes (weak passwords, mismatched confirm password, invalid email)

---

### **Basic Complete Example**

```jsx
  const [confirmPassword, setConfirmPassword] = useState('');

  // Simple Validation Function
  const validateForm = () => {
    if (!name.trim()) {
      Alert.alert('Validation Error', 'Name is required');
      return false;

    if (!email.trim()) {
      Alert.alert('Validation Error', 'Email is required');
      return false;
    }

    if (!emailRegex.test(email)) {
      Alert.alert('Validation Error', 'Please enter a valid email address');
      return false;
    }
    if (password.length < 6) {
      Alert.alert('Validation Error', 'Password must be at least 6 characters');
      return false;

    if (password !== confirmPassword) {
      Alert.alert('Validation Error', 'Passwords do not match');
      return false;

    return true;

          onPress={handleSignup}
          disabled={loading}
        >
          {loading ? (
            <ActivityIndicator color="#fff" />
          ) : (
```

## 3. Login

**Description**: Login allows a registered user to authenticate and receive tokens so they can access protected parts of the app.

### **What is Login?**

After a user has signed up, they need a way to prove their identity. The Login screen collects email and password, sends them to the backend, and (if correct) receives:

- **Access Token** (short-lived)
- **Refresh Token** (long-lived)
- User information (optional)

A good Login screen should handle:
- Input validation
- Loading state
- Success → Save tokens + Navigate to Home
- Invalid credentials
- Network errors
- “Forgot Password” link (optional)

## 4️. Access Token

**Description**: An Access Token is a short-lived JWT that allows the user to access protected APIs and resources.

### **What is an Access Token?**

After a successful login, the backend returns an **Access Token**. This token acts like a temporary digital key. Every time the app needs to fetch private data (profile, orders, posts, etc.), it must send this token to the server.

Because Access Tokens are short-lived (usually 15 minutes to 1 hour), even if someone steals the token, the damage is limited.

---

### **Why Access Tokens Expire**

- **Security**: Reduces the window of opportunity if the token is stolen
- **Force Refresh**: Encourages the use of Refresh Tokens
- **Revocation Control**: Easier to invalidate short-lived tokens

---

### **How to Send Access Token with Every Request**

The standard way is using the **Authorization Header** with the `Bearer` scheme:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

---

### **Basic Complete Example (Using Axios Interceptor)**

```jsx
import axios from 'axios';
import * as SecureStore from 'expo-secure-store';

// Create a custom axios instance
const api = axios.create({
  baseURL: 'https://your-api.com/api',
});

// Request Interceptor – Automatically attach Access Token
api.interceptors.request.use(
  async (config) => {
    const accessToken = await SecureStore.getItemAsync('accessToken');
    
    if (accessToken) {
      config.headers.Authorization = `Bearer ${accessToken}`;
    }
    
    return config;
  },
  (error) => {
    return Promise.reject(error);
  }
);

export default api;
```

**Using the API instance:**
```jsx
import api from './api';

// This request will automatically include the Access Token
const getProfile = async () => {
  try {
    const response = await api.get('/profile');
    console.log('User Profile:', response.data);
  } catch (error) {
    console.log('Error fetching profile:', error.response?.data);
  }
};
```

---

### **Manual Way (Without Interceptor)**

```jsx
const accessToken = await SecureStore.getItemAsync('accessToken');

const response = await axios.get('https://your-api.com/api/profile', {
  headers: {
    Authorization: `Bearer ${accessToken}`,
  },
});
```

---

### **Important Concepts**

| Concept                  | Description                                      | Best Practice |
|-------------------------|--------------------------------------------------|---------------|
| Short Lifetime          | 15 min – 1 hour                                  | Recommended |
| Bearer Scheme           | Standard format for JWT                          | Always use it |
| Automatic Attachment    | Use Axios Interceptors                           | Cleaner code |
| Token Expiration Check  | Backend returns 401 when expired                 | Handle in interceptor |

---

### **More Examples**

#### **1. Checking if Token is Expired (Client-side – Optional)**
```jsx
import jwtDecode from 'jwt-decode'; // install: npm install jwt-decode

const isTokenExpired = (token) => {
  try {
    const decoded = jwtDecode(token);
    const currentTime = Date.now() / 1000;
    return decoded.exp < currentTime;
  } catch (error) {
    return true; // Invalid token
  }
};
```

#### **2. Handling 401 (Unauthorized) Response**
```jsx
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      // Access Token expired → Try to refresh (we'll cover this next)
      console.log('Access Token expired');
    }
    return Promise.reject(error);
  }
);
```

---

### **Backend Side (What Happens)**

When the server receives a request:

1. It extracts the token from the `Authorization` header
2. Verifies the signature using the secret key
3. Checks if the token has expired
4. If valid → Allows access to the resource
5. If invalid or expired → Returns `401 Unauthorized`

---

**Pro Tips**:
- Never hardcode the Access Token
- Always attach it using interceptors for cleaner code
- Treat 401 responses carefully (they usually mean the token expired)
- Keep Access Token lifetime short for better security

## 5. Refresh Token

**Description**: A Refresh Token is a long-lived token used to obtain a new Access Token when the current one expires — without forcing the user to log in again.

### **What is a Refresh Token?**

Access Tokens are intentionally short-lived for security reasons. When an Access Token expires, the app should not ask the user to enter their password again. Instead, it uses the **Refresh Token** to silently get a new Access Token from the server.

This creates a smooth user experience while maintaining good security.

---

### **How the Refresh Token Flow Works**

```text
1. User logs in → Receives Access Token + Refresh Token
2. App uses Access Token for API calls
3. Access Token expires
4. App detects 401 Unauthorized
5. App sends Refresh Token to /refresh endpoint
6. Server verifies Refresh Token
7. Server issues a new Access Token (and optionally a new Refresh Token)
8. App continues working normally
```

---

### **Basic Complete Example (Automatic Token Refresh)**

```jsx
import axios from 'axios';
import * as SecureStore from 'expo-secure-store';

const api = axios.create({
  baseURL: 'https://your-api.com/api',
});

// Request Interceptor – Attach Access Token
api.interceptors.request.use(async (config) => {
  const accessToken = await SecureStore.getItemAsync('accessToken');
  if (accessToken) {
    config.headers.Authorization = `Bearer ${accessToken}`;
  }
  return config;
});

// Response Interceptor – Handle Token Expiration
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // If Access Token expired (401) and we haven't already tried to refresh
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;

      try {
        const refreshToken = await SecureStore.getItemAsync('refreshToken');

        if (!refreshToken) {
          // No refresh token → Force logout
          await logoutUser();
          return Promise.reject(error);
        }

        // Call Refresh Token API
        const response = await axios.post('https://your-api.com/api/auth/refresh', {
          refreshToken,
        });

        const { accessToken, refreshToken: newRefreshToken } = response.data;

        // Save new tokens
        await SecureStore.setItemAsync('accessToken', accessToken);
        if (newRefreshToken) {
          await SecureStore.setItemAsync('refreshToken', newRefreshToken);
        }

        // Retry the original request with new Access Token
        originalRequest.headers.Authorization = `Bearer ${accessToken}`;
        return api(originalRequest);
      } catch (refreshError) {
        // Refresh failed → Logout user
        await logoutUser();
        return Promise.reject(refreshError);
      }
    }

    return Promise.reject(error);
  }
);

// Helper function to logout
const logoutUser = async () => {
  await SecureStore.deleteItemAsync('accessToken');
  await SecureStore.deleteItemAsync('refreshToken');
  await SecureStore.deleteItemAsync('user');
  // Navigate to Login screen (you'll handle this with navigation or context)
};

export default api;
```

---

### **Important Concepts**

| Concept                  | Description                                      | Best Practice |
|-------------------------|--------------------------------------------------|---------------|
| Token Rotation          | Server issues a new Refresh Token on every refresh | More secure |
| Single Use Refresh Tokens | Old Refresh Token becomes invalid after use     | Prevents reuse attacks |
| Automatic Refresh       | Handled silently in the interceptor              | Best UX |
| Refresh Failure         | Force the user to log in again                   | Security first |

---

### **More Examples**

#### **1. Manual Refresh Function**
```jsx
const refreshAccessToken = async () => {
  const refreshToken = await SecureStore.getItemAsync('refreshToken');
  
  const response = await axios.post('/api/auth/refresh', {
    refreshToken,
  });

  await SecureStore.setItemAsync('accessToken', response.data.accessToken);
  return response.data.accessToken;
};
```

#### **2. Checking if Refresh Token Exists**
```jsx
const hasValidSession = async () => {
  const refreshToken = await SecureStore.getItemAsync('refreshToken');
  return !!refreshToken;
};
```

---

### **Backend Response Example (Successful Refresh)**

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "newRefreshTokenHere..."   // Optional (token rotation)

```

**Pro Tips**:
- Always handle the case when the Refresh Token itself is expired or revoked
- Prefer **Token Rotation** (issuing a new Refresh Token every time)
- Never store Refresh Tokens in AsyncStorage
- Keep the Refresh Token lifetime reasonable (7–30 days)

## 6️. Secure Authentication

**Description**: Simply getting tokens is not enough. You must store them securely, manage sessions properly, and follow production-level security practices.

### **What is Secure Authentication?**

Secure Authentication means protecting user credentials and tokens so that even if the device is compromised or the app is reverse-engineered, the damage is minimized.

Key principles:
- Never store passwords
- Store tokens securely
- Auto-login only when safe
- Clear tokens on logout
- Protect sensitive screens

---

### **1. Secure Token Storage**

**Never use `AsyncStorage` for tokens.**  
Use **`expo-secure-store`** instead — it encrypts data using the device’s secure hardware (Keychain on iOS, Keystore on Android).

```bash
npx expo install expo-secure-store
```

**Example:**
```jsx
import * as SecureStore from 'expo-secure-store';

// Save
await SecureStore.setItemAsync('accessToken', accessToken);
await SecureStore.setItemAsync('refreshToken', refreshToken);

// Read
const token = await SecureStore.getItemAsync('accessToken');

// Delete (on logout)
await SecureStore.deleteItemAsync('accessToken');
await SecureStore.deleteItemAsync('refreshToken');
```

---

### **2. Authentication Context (Recommended Pattern)**

Create a global Auth Context so every screen can easily check if the user is logged in.

```jsx
import React, { createContext, useState, useEffect, useContext } from 'react';
import * as SecureStore from 'expo-secure-store';
import api from './api'; // your axios instance with interceptors

const AuthContext = createContext();

export const AuthProvider = ({ children }) => {
  const [user, setUser] = useState(null);
  const [isLoading, setIsLoading] = useState(true);
  const [isAuthenticated, setIsAuthenticated] = useState(false);

  // Check for existing session on app start
  useEffect(() => {
    const checkAuth = async () => {
      try {
        const accessToken = await SecureStore.getItemAsync('accessToken');
        const userData = await SecureStore.getItemAsync('user');

        if (accessToken && userData) {
          setUser(JSON.parse(userData));
          setIsAuthenticated(true);
        }
      } catch (error) {
        console.log('Auth check failed', error);
      } finally {
        setIsLoading(false);
      }
    };

    checkAuth();
  }, []);

  const login = async (accessToken, refreshToken, userData) => {
    await SecureStore.setItemAsync('accessToken', accessToken);
    await SecureStore.setItemAsync('refreshToken', refreshToken);
    await SecureStore.setItemAsync('user', JSON.stringify(userData));
    
    setUser(userData);
    setIsAuthenticated(true);
  };

  const logout = async () => {
    await SecureStore.deleteItemAsync('accessToken');
    await SecureStore.deleteItemAsync('refreshToken');
    await SecureStore.deleteItemAsync('user');
    
    setUser(null);
    setIsAuthenticated(false);
  };

  return (
    <AuthContext.Provider
      value={{
        user,
        isAuthenticated,
        isLoading,
        login,
        logout,
      }}
    >
      {children}
    </AuthContext.Provider>
  );
};

export const useAuth = () => useContext(AuthContext);
```

---

### **3. Auto Login on App Start**

The `useEffect` in the AuthProvider above already handles **Auto Login**.  
When the app opens, it checks if valid tokens exist and automatically logs the user in.

---

### **4. Logout Function**

```jsx
const { logout } = useAuth();

const handleLogout = async () => {
  await logout();
  // Optionally call backend logout API to invalidate refresh token
  navigation.replace('Login');
};
```

---

### **5. Protected Screens**

```jsx
import { useAuth } from './AuthContext';
import { ActivityIndicator, View } from 'react-native';

const ProtectedScreen = ({ children }) => {
  const { isAuthenticated, isLoading } = useAuth();

  if (isLoading) {
    return (
      <View style={{ flex: 1, justifyContent: 'center' }}>
        <ActivityIndicator size="large" />
      </View>
    );
  }

  if (!isAuthenticated) {
    // Redirect to Login (handled better with navigation)
    return null;
  }

  return children;
};
```

---

### **Best Security Practices**

| Practice                        | Why It’s Important                              |
|--------------------------------|-------------------------------------------------|
| Use SecureStore                | Tokens are encrypted at rest                    |
| Short Access Token lifetime    | Limits damage if stolen                         |
| Token Rotation                 | Makes stolen refresh tokens less useful         |
| Clear tokens on logout         | Prevents session hijacking                      |
| Never store passwords          | Backend should only store hashed passwords      |
| HTTPS only                     | Prevents man-in-the-middle attacks              |
| Logout from all devices option | Important for security-conscious apps           |

---

### **Common Mistakes to Avoid**

- Storing tokens in AsyncStorage
- Storing passwords on the device
- Not clearing tokens on logout
- Not handling expired refresh tokens
- Hardcoding API keys or secrets in the app

---

**Pro Tip**: Combine **AuthContext + SecureStore + Axios Interceptors** for a clean, production-ready authentication system.

## 7️. Protected Routes

**Description**: Protected Routes ensure that only authenticated users can access certain screens (Home, Profile, Settings, Orders, etc.).

### **What are Protected Routes?**

Some screens in your app should only be visible after the user has successfully logged in. If a user tries to access these screens without being authenticated, they should be automatically redirected to the Login screen.

This is a fundamental part of any secure authentication system.

---

### **Basic Complete Example (Using React Navigation + Auth Context)**

```jsx
import React from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { useAuth } from './AuthContext';
import { ActivityIndicator, View } from 'react-native';

// Screens
import LoginScreen from './screens/LoginScreen';
import SignupScreen from './screens/SignupScreen';
import HomeScreen from './screens/HomeScreen';
import ProfileScreen from './screens/ProfileScreen';

const Stack = createNativeStackNavigator();

const AppNavigator = () => {
  const { isAuthenticated, isLoading } = useAuth();

  // Show loading spinner while checking authentication status
  if (isLoading) {
    return (
      <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
        <ActivityIndicator size="large" color="#007AFF" />
      </View>
    );
  }

  return (
    <NavigationContainer>
      <Stack.Navigator screenOptions={{ headerShown: false }}>
        {isAuthenticated ? (
          // Authenticated Stack (Protected Routes)
          <>
            <Stack.Screen name="Home" component={HomeScreen} />
            <Stack.Screen name="Profile" component={ProfileScreen} />
            {/* Add more protected screens here */}
          </>
        ) : (
          // Public Stack (Auth Screens)
          <>
            <Stack.Screen name="Login" component={LoginScreen} />
            <Stack.Screen name="Signup" component={SignupScreen} />
          </>
        )}
      </Stack.Navigator>
    </NavigationContainer>
  );
};

export default AppNavigator;
```

---

### **How It Works**

1. App starts → `AuthProvider` checks if tokens exist
2. While checking → Show loading spinner
3. If tokens exist and valid → Show **Protected Stack** (Home, Profile, etc.)
4. If no tokens → Show **Auth Stack** (Login + Signup)
5. After successful login → `isAuthenticated` becomes `true` → Navigation automatically switches to Protected Stack
6. After logout → `isAuthenticated` becomes `false` → User is taken back to Login

---

### **More Advanced Example (With Nested Navigators)**

```jsx
// You can also use different navigators
{isAuthenticated ? (
  <Stack.Navigator>
    <Stack.Screen name="MainTabs" component={TabNavigator} />
    <Stack.Screen name="Settings" component={SettingsScreen} />
  </Stack.Navigator>
) : (
  <Stack.Navigator>
    <Stack.Screen name="Login" component={LoginScreen} />
    <Stack.Screen name="Signup" component={SignupScreen} />
  </Stack.Navigator>
)}
```

---

### **Protecting Individual Screens (Alternative Approach)**

```jsx
import { useAuth } from './AuthContext';
import { useEffect } from 'react';

const ProfileScreen = ({ navigation }) => {
  const { isAuthenticated } = useAuth();

  useEffect(() => {
    if (!isAuthenticated) {
      navigation.replace('Login');
    }
  }, [isAuthenticated]);

  if (!isAuthenticated) return null;

  return (
    <View>
      {/* Profile content */}
    </View>
  );
};
```

---

### **Important Concepts**

| Concept                      | Description                                      | Recommendation |
|-----------------------------|--------------------------------------------------|----------------|
| Conditional Stack Rendering | Show different navigators based on auth state    | Cleanest approach |
| Loading State               | Prevent flash of wrong screen                    | Always show spinner |
| `replace` instead of `navigate` | Prevent going back to Login after success     | Better UX |
| Nested Navigators           | Tabs + Stack for complex apps                    | Very common |

---

### **Best Practices**

- Always show a loading indicator while checking authentication
- Use `navigation.replace` after login/logout
- Keep public and protected screens completely separated
- Never put sensitive screens in the public stack
- Combine this with the Axios interceptor for full protection

---

**Pro Tip**: This pattern (Auth Context + Conditional Navigation) is used by almost every production React Native app.

## 8️. Complete Authentication Flow

**Description**: Putting everything together into a production-ready authentication system.

### **Full Authentication Lifecycle**

```text
App Launch
    ↓
Check SecureStore for Tokens
    ↓
Tokens Found?
    ↓
YES → Try Access Token
    ↓
Valid? → Home Screen
    ↓
Expired? → Use Refresh Token
    ↓
Refresh Success? → Save New Tokens → Home
    ↓
Refresh Failed? → Clear Tokens → Login Screen
    ↓
NO Tokens → Login / Signup Screen
```

---

```text
my-app/
├── app/
│   ├── _layout.tsx                     ← Root Layout (AuthProvider + Slot)

│   │
│   ├── (auth)/                         ← Public Auth Group
│   │   ├── _layout.tsx
│   │   ├── login.tsx
│   │   └── signup.tsx
│   │
│   └── (tabs)/                         ← Protected Tabs Group
│       ├── _layout.tsx
│       ├── index.tsx                   ← Home Screen

│
├── src/
```

### **Best Practices Summary**

| Area                        | Best Practice                                      |
|----------------------------|----------------------------------------------------|
| Token Storage              | Always use `expo-secure-store`                     |
| Access Token Lifetime      | Keep short (15–60 minutes)                         |
| Refresh Token              | Use Token Rotation when possible                   |
| Navigation                 | Conditional stacks based on `isAuthenticated`      |

| Logout                     | Clear all tokens + call backend logout endpoint    |

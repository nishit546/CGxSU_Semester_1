
# React Native – Testing

Testing verifies that your application behaves correctly. Instead of manually checking everything after every change, automated tests verify your code and help catch bugs early.

---

## 1. What is Testing?

Testing is the process of verifying that your application works as expected.

Instead of manually checking every feature after every code change, automated tests run quickly and consistently.

**Benefits of Testing:**
- Detect bugs early
- Improve code quality
- Refactor with confidence
- Prevent regressions
- Improve maintainability
- Document expected behavior

**Real-life Analogy:**
Testing is like having a quality control team that checks every product on the assembly line before it reaches customers. Automated tests act as that quality control for your code.

---

## 2. Types of Testing

| Type                    | Purpose                                      | Scope |
|-------------------------|----------------------------------------------|-------|
| Unit Testing            | Test individual functions or components      | Small |
| Integration Testing     | Test multiple components working together    | Medium |
| Snapshot Testing        | Detect unexpected UI changes                 | UI |
| End-to-End Testing      | Test complete user flows                     | Full App |

## 4. Writing Your First Test

### Example Function

```jsx
// math.js
export function add(a, b) {
  return a + b;
}
```

### Test File

```jsx
// math.test.js
import { add } from "./math";

test("adds two numbers correctly", () => {
  expect(add(2, 3)).toBe(5);
});

test("adds negative numbers", () => {
  expect(add(-2, -3)).toBe(-5);
});
```

### Basic Structure of a Test

```jsx
test("description of what is being tested", () => {
  // Arrange
  // Act
  // Assert
  expect(actualValue).toBe(expectedValue);
});
```

## 5. React Native Testing Library (RNTL)

React Native Testing Library helps you test components the way users interact with them. It focuses on testing behavior rather than implementation details.

### Installation

```bash
npm install --save-dev @testing-library/react-native
```

### Basic Example

```jsx
import { render, screen } from "@testing-library/react-native";
import App from "./App";

test("renders the welcome title", () => {
  render(<App />);
  expect(screen.getByText("Welcome")).toBeTruthy();
});
```

### Common Queries

| Query                | Purpose                              |
|----------------------|--------------------------------------|
| `getByText`          | Find element by text content         |
| `getByTestId`        | Find element by testID prop          |
| `getByPlaceholderText` | Find input by placeholder          |
| `queryByText`        | Returns null if not found (safer)    |
| `findByText`         | Async version for elements that appear later |

### Example with User Interaction

```jsx
import { render, fireEvent, screen } from "@testing-library/react-native";
import LoginScreen from "./LoginScreen";

test("calls login function when button is pressed", () => {
  const mockLogin = jest.fn();
  render(<LoginScreen onLogin={mockLogin} />);

  fireEvent.press(screen.getByText("Login"));
  expect(mockLogin).toHaveBeenCalled();
});
```

## 6. Unit Testing

Unit testing verifies a single unit of code in isolation.

### Example

```jsx
function multiply(a, b) {
  return a * b;
}
```

```jsx
test("multiplies two numbers", () => {
  expect(multiply(2, 5)).toBe(10);
});
```

### What Should Be Unit Tested?

- Utility functions
- Custom hooks
- Validation logic
- Reducers
- Business logic
- Helper functions

Unit tests should be fast, independent, and focused on one thing.

## 7. Component Testing

Component testing verifies that a React Native component renders correctly and responds to user interactions.

### Basic Example

```jsx
import { render, screen } from "@testing-library/react-native";
import { Button } from "react-native";

test("renders login button", () => {
  render(<Button title="Login" />);
  expect(screen.getByText("Login")).toBeTruthy();
});
```

### Testing with Props

```jsx
import { render, screen } from "@testing-library/react-native";
import UserCard from "./UserCard";

test("displays user name", () => {
  render(<UserCard name="Rajesh" />);
  expect(screen.getByText("Rajesh")).toBeTruthy();
});
```

### Testing User Interactions

```jsx
import { render, fireEvent, screen } from "@testing-library/react-native";
import Counter from "./Counter";

test("increments count when button is pressed", () => {
  render(<Counter />);
  
  fireEvent.press(screen.getByText("Increment"));
  expect(screen.getByText("Count: 1")).toBeTruthy();
});
```

### Best Practice

Prefer testing what the user sees and does rather than internal implementation details (such as state variables or method names).

## 8. Snapshot Testing

Snapshot testing captures the rendered output of a component and compares it against a previously stored snapshot.

### Example

```jsx
import renderer from "react-test-renderer";
import App from "./App";

test("matches snapshot", () => {
  const tree = renderer.create(<App />).toJSON();
  expect(tree).toMatchSnapshot();
});
```

When you run the test for the first time, Jest creates a snapshot file. On later runs, it compares the current output with the saved snapshot.

### Benefits

- Detect accidental UI changes
- Easy regression testing
- Quick visual verification of structure

### When Snapshot Tests Fail

If the UI changes intentionally, you can update the snapshot:

```bash
npm test -- -u
```

### Important Notes

- Do not overuse snapshot tests
- Prefer smaller, focused snapshots
- Always review snapshot changes carefully before updating them

## 9. Mocking

Mocking is used to replace real implementations (especially external services) with controlled fake versions during tests.

### Example – Mocking Axios

```jsx
import axios from "axios";
jest.mock("axios");

test("fetches users successfully", async () => {
  axios.get.mockResolvedValue({
    data: [{ id: 1, name: "Rajesh" }],
  });

  // Call the function that uses axios
  // Assert the expected result
});
```

### Common Use Cases for Mocking

- API calls
- Async functions
- Database operations
- External libraries
- Navigation
- Device APIs (camera, location, etc.)

Mocking keeps tests fast, reliable, and independent of external systems.

## 10. Common Matchers

Jest provides many matchers to make assertions clear and readable.

```jsx
expect(value).toBe(5);                 // Exact equality (===)
expect(value).toEqual({ name: "Rajesh" }); // Deep equality
expect(value).toBeTruthy();
expect(value).toBeFalsy();
expect(value).toBeNull();
expect(value).toBeUndefined();
expect(array).toContain("item");
expect(string).toMatch(/hello/);
expect(fn).toHaveBeenCalled();
expect(fn).toHaveBeenCalledWith(arg);
expect(promise).resolves.toBe(value);
expect(promise).rejects.toThrow();
```

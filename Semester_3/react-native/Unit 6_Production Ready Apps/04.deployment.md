
# React Native – Deployment

Deployment is the process of converting your React Native source code into a production-ready mobile application and publishing it so users can download it from the Google Play Store or Apple App Store.


## 1. What is Deployment?

Deployment means taking your finished application and making it available to real users.

**Deployment Process:**

```text
Develop App
      |
Testing
      |
Build
      |
Signing
      |
Store Upload
      |
Users Download App
```

Without proper deployment, even a perfect application cannot reach users.

---

## 2. APK Build

**APK (Android Package Kit)** is the traditional format used to install Android applications.

### Advantages
- Easy to test
- Easy to share with clients or testers
- Useful for internal distribution
- Can be installed directly on Android devices

### Limitations
- Google Play now prefers AAB format
- Larger file size compared to AAB
- Not optimized for different device configurations

### Generate APK using EAS

```bash
eas build --platform android --profile preview
```

or for a production-like build:

```bash
eas build --platform android
```

---

## 3. AAB Build

**AAB (Android App Bundle)** is Google’s recommended format for publishing apps on the Google Play Store.

### Advantages
- Smaller download size for users
- Google Play generates optimized APKs for different devices
- Required for new apps on Google Play
- Better performance and efficiency

### Generate AAB using EAS

```bash
eas build --platform android
```

By default, EAS produces an AAB file suitable for Play Store upload when using the production profile.

---

## 4. EAS Build

**Expo Application Services (EAS)** allows you to build Android and iOS apps in the cloud without needing a local Mac or complex native environment setup.

### Installation

```bash
npm install -g eas-cli
```

### Login

```bash
eas login
```

### Configure the Project

```bash
eas build:configure
```

This command creates an `eas.json` file where you define build profiles (development, preview, production).

### Common Build Commands

```bash
# Android build
eas build --platform android

# iOS build
eas build --platform ios

# Both platforms
eas build --platform all
```

### Example eas.json

```json
{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}
```

EAS handles native compilation, signing (when configured), and produces downloadable builds.

## 5. Play Store Release

### Steps to Publish on Google Play Store

1. Create a Google Play Console account
2. Create a new app
3. Upload the AAB file
4. Fill Store Listing (title, description, screenshots)
5. Upload app icon and feature graphic
6. Add Privacy Policy URL
7. Complete Content Rating questionnaire
8. Set up Pricing and Distribution
9. Create a Production release and roll it out

### Release Checklist

- App icon is correct
- Splash screen looks good
- Version number is updated
- Build is signed
- Release build has been tested on real devices
- Privacy policy is available
- Screenshots are uploaded for required device types

---

## 6. App Store Release (iOS)

Publishing to the Apple App Store has stricter requirements than Android.

### Requirements
- Active Apple Developer Account ($99/year)
- App Store Connect access
- Signed build (EAS can handle this)
- Proper privacy and content information

### Steps to Publish

1. Create a new app in App Store Connect
2. Upload the build (via EAS Submit or Transporter)
3. Fill App Information (name, subtitle, category)
4. Upload screenshots for required device sizes
5. Add Privacy Policy URL
6. Complete App Privacy details
7. Set pricing and availability
8. Submit for App Review

### Review Time
Usually takes 1–3 days, but can sometimes take longer.

### Using EAS Submit

```bash
eas submit --platform ios
```

EAS can automatically upload the latest build to App Store Connect.

---

## 7. Versioning

Every release must have a new version number.

### Example in app.json

```json
{
  "expo": {
    "version": "1.2.0",
    "android": {
      "versionCode": 12
    },
    "ios": {
      "buildNumber": "12"
    }
  }
}
```

### Meaning of Each Field

| Field            | Platform   | Purpose                              |
|------------------|------------|--------------------------------------|
| `version`        | Both       | User-visible version (1.2.0)         |
| `versionCode`    | Android    | Internal integer that must increase  |
| `buildNumber`    | iOS        | Internal string that must increase   |

**Important Rules:**
- `versionCode` must always increase for every Play Store upload
- `buildNumber` must always increase for every App Store upload
- Users see the `version` field

---

## 8. App Signing

App Signing proves that the application comes from the original developer and has not been tampered with.

### Android
- Uses a Keystore file
- Contains private key and certificate
- EAS can manage the keystore automatically
- SHA keys are used for services like Firebase and Google Maps

### iOS
- Requires Certificates
- Requires Provisioning Profiles
- EAS can manage credentials for you

### Recommendation
Let EAS manage credentials whenever possible. Store backup keys securely if you generate them yourself. Losing signing keys can prevent future updates.

## 9. Release Checklist

Before publishing any build, go through this checklist:

- Remove all debug console logs
- Test the release build thoroughly
- Verify all permissions are necessary and declared
- Optimize images and assets
- Confirm production API URLs are correct
- Update version, versionCode, and buildNumber
- Generate a properly signed build
- Test on real Android and iOS devices
- Check privacy policy and store listing details
- Verify app icon and splash screen

---

## 10. Deployment Flow

```text
Complete Development
        |
Run Tests
        |
Update Version Numbers
        |
Build with EAS (APK / AAB / IPA)
        |
Sign the App
        |
Upload to Play Store / App Store
        |
Complete Store Listing
        |
Submit for Review
        |
Published
```
